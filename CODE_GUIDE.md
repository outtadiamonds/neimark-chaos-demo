## 1. Шпаргалка: самые нужные команды

Все команды запускаются из папки проекта `C:\idk\phys`.

| Что нужно | Команда |
|---|---|
| Запустить программу из исходников | `.venv/Scripts/python main.py` |
| Прогнать тесты | `.venv/Scripts/python tools/build.py test` |
| **Собрать Windows-архив** | `.venv/Scripts/python tools/build.py` или двойной щелчок по `build.bat` |
| Собрать Windows и проверить запуск | `.venv/Scripts/python tools/build.py --check` |
| **Собрать Linux-архив** (Docker Desktop запущен вручную) | `.venv/Scripts/python tools/build.py linux` |
| Собрать оба архива | `.venv/Scripts/python tools/build.py all` |
| Пересобрать теорию после правки текста | `.venv/Scripts/python tools/build.py theory` |
| Собрать без тестов (быстрее) | добавить `--no-tests` |

Готовые архивы появляются в `dist/`:
- `NeimarkCorrelation-windows-x64.zip`;
- `NeimarkCorrelation-linux-x64.zip`.

**Главное правило:** правка в коде сама в архив не попадает. После любого изменения архивы нужно собрать заново. Скрипт сборки в конце печатает дату сборки каждого архива — по ней видно, свежий ли он.

## 2. Подготовка компьютера (один раз)

### 2.1. Что нужно установить

- **Python 3.12 или новее.** Проект собирался на Python 3.14.
- **Docker Desktop** — только для Linux-сборки. Для Windows-сборки не нужен.

### 2.2. Виртуальное окружение

**Виртуальное окружение** (`.venv`) — отдельная папка со своей копией Python и библиотек проекта. Оно не смешивается с другими проектами на компьютере. Создаётся один раз:

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements-dev.txt
```

`requirements-dev.txt` содержит три библиотеки с точными версиями:

| Библиотека | Зачем | Попадает в готовую программу? |
|---|---|---|
| `pygame-ce==2.5.8` | окно, рисование, мышь, клавиатура | да |
| `pyinstaller==6.22.3` | превращает Python-программу в `.exe` | нет |
| `typst==0.15.0` | вёрстка теории в PDF и картинки | нет |

Если папка `.venv` уже есть, ничего делать не нужно.

На Linux и macOS вместо `.venv/Scripts/python` пишется `.venv/bin/python`.

## 3. Сборка и обновление программы

### 3.1. Быстрый путь: `tools/build.py`

Скрипт `tools/build.py` делает всю сборку одной командой. Варианты:

```
python tools/build.py               # Windows-архив
python tools/build.py linux         # Linux-архив
python tools/build.py all           # оба
python tools/build.py theory        # рисунки + теория
python tools/build.py test          # только тесты
python tools/build.py run           # запустить программу
```

Флаги:
- `--no-tests` — пропустить тесты (экономит около 5 секунд);
- `--check` — после сборки запустить собранную программу и сохранить скриншот:
  - для Windows — `build/check-windows.png`;
  - для Linux — `build/linux-test/check-*.png`, программа запускается на чистой Ubuntu 20.04.

Что делает скрипт для Windows, по шагам:
1. Запускает тесты. Если хоть один упал, сборка останавливается.
2. Удаляет старые `dist/windows` и `build/work-windows`.
3. Вызывает PyInstaller со spec-файлом `build/neimark.spec`.
4. Вызывает `tools/package.py`: упаковывает папку программы, PDF теории и README в zip.
5. С флагом `--check` запускает собранный `.exe` и делает скриншот.
6. Печатает список архивов с размером и датой сборки.

Для Linux:
1. Проверяет командой `docker info`, что Docker запущен. Если нет — выводит сообщение и останавливается. Сам Docker скрипт **не запускает**: Docker Desktop нужно открыть вручную.
2. Запускает контейнер `python:3.12-slim-bullseye` и внутри него скрипт `build/build_linux.sh`.

`build.bat` — то же самое для двойного щелчка в проводнике. Ему можно передать аргументы из командной строки: `build.bat all --check`.

Время сборки на этом компьютере: Windows около 40 секунд, Linux около 1–2 минут (первый раз дольше: Docker скачивает образ).

### 3.2. Что пересобирать после какого изменения

| Что изменили | Что сделать |
|---|---|
| код в `ncorr/` или `main.py` | `build.py all` |
| `assets/authors.json`, фото, логотипы, шрифты | `build.py all` |
| текст теории `theory/*.typ` | `build.py theory`, затем `build.py all` |
| вид плоскости параметров (`param_plane.py`) | `build.py theory` (рисунок в теории рисуется тем же кодом), затем `build.py all` |
| `tools/make_figures.py` | `build.py theory`, затем `build.py all` |
| иконку | `python tools/make_icon.py`, затем `build.py` |
| README внутри архива (`tools/package.py`) | `build.py all` |

### 3.3. Самый быстрый цикл разработки

Пока вы правите программу, собирать архив не нужно. Цикл такой:

1. Поправили код.
2. `python main.py` — посмотрели.
3. Повторили.

Для быстрого перехода сразу на нужный экран есть аргументы командной строки (раздел 14.2):

```bash
.venv/Scripts/python main.py --screen demo --preset E --build
```

Архивы собираются один раз в конце, когда всё готово.

### 3.4. Сборка вручную, без скрипта

Если скрипт по какой-то причине не работает, вот те же команды по отдельности.

Windows:

```bash
.venv/Scripts/pyinstaller --noconfirm --clean --distpath dist/windows --workpath build/work-windows build/neimark.spec
.venv/Scripts/python tools/package.py windows dist/windows/NeimarkCorrelation dist/NeimarkCorrelation-windows-x64.zip
```

Linux (в Git Bash в начало добавьте `MSYS_NO_PATHCONV=1 `):

```bash
docker run --rm -v "C:/idk/phys:/src" python:3.12-slim-bullseye sh /src/build/build_linux.sh
```

### 3.5. Типичные ошибки сборки

| Сообщение | Причина | Что делать |
|---|---|---|
| `Docker не запущен` | Docker Desktop закрыт или ещё загружается | открыть Docker Desktop, дождаться значка «Engine running», повторить |
| `failed to connect to the docker API` | то же | то же |
| `FAILED (failures=...)` после тестов | изменение что-то сломало | прочитать, какой тест упал (раздел 15); собрать с `--no-tests` можно, но лучше починить |
| `PermissionError` при удалении `dist/windows` | собранная программа сейчас открыта | закрыть программу |
| `ModuleNotFoundError: No module named 'typst'` | не установлены зависимости | `pip install -r requirements-dev.txt` |
| Windows-версию можно собрать только на Windows | запуск на Linux/macOS | PyInstaller не умеет собирать под другую ОС; для Linux используйте Docker |

## 4. Общая идея и технологии

### 4.1. Что делает программа

1. Демонстрация из двух вкладок с общим переключателем сверху панели.
   - **«Движение осциллятора»** (`motion.py`, часть А. С. Григорьева): груз на пружине, фазовая траектория, скорость $v(t)$ как её проекция, отображение за полпериода. Вторая, близкая траектория показывает, как из динамической неопределённости появляется случайность и где точка бифуркации.
   - **«Корреляционная функция»** (`demo.py`): генерирует последовательность $y_n$ по той же формуле и наглядно строит корреляционную функцию — сдвигает копию, перемножает отклонения, усредняет.
3. Независимо вычисляет точную теоретическую корреляционную функцию и рисует её поверх эксперимента.
4. Показывает теорию, авторов, переключает язык.

### 4.2. Почему выбраны эти технологии

| Технология | Почему |
|---|---|
| **Python** | простой язык; на нём сделано большинство демонстраций на сайте курса |
| **pygame-ce** | библиотека для 2D-графики и окон; то же использует проект «Броуновская частица под действием шумов» на сайте. `-ce` — активно поддерживаемая версия pygame |
| **без numpy и matplotlib** | вся математика на чистом Python. Сборка меньше (около 25 МБ вместо 80+), меньше зависимостей, графики полностью под нашим контролем. Скорости хватает: выборки до 100 000 чисел |
| **PyInstaller** | упаковывает Python и все библиотеки в папку с `.exe`, на компьютере пользователя ничего ставить не нужно |
| **Docker** | позволяет собрать Linux-версию на Windows, причём на старом Linux, чтобы она работала на большинстве дистрибутивов |
| **Typst** | язык вёрстки, похожий на LaTeX, но ставится одной pip-командой. Из одного текста получаются и PDF, и картинки страниц для программы |

### 4.3. Принцип устройства кода

Код разделён на три слоя:

```
физика (physics/)  ─────►  интерфейс (ui/, screens/)  ─────►  окно (app.py)
считает числа             рисует числа и реагирует на мышь     главный цикл
ничего не знает           знает про физику                      знает про экраны
про графику
```

Физику можно запускать и тестировать без окна. Это видно по тестам: `test_physics.py` вообще не создаёт окно.

## 6. Как программа работает во время выполнения

### 6.1. Запуск

```
python main.py
   │
   ├─ разбирает аргументы (--lang, --screen, ...)
   ├─ App(...)                  создаёт окно и все пять экранов
   │    ├─ MenuScreen
   │    ├─ MotionScreen         ← вкладка «Движение осциллятора»
   │    ├─ DemoScreen           ← вкладка «Корреляционная функция»: сразу генерируется ряд и считается теория
   │    ├─ TheoryScreen
   │    └─ AuthorsScreen
   └─ app.run()                 главный цикл, пока окно не закрыто
```

Все экраны создаются один раз при запуске и живут до конца. При переходе между ними ничего не создаётся заново — меняется только «активный» экран. Поэтому, например, построенные столбики сохраняются, если сходить в меню и вернуться.

### 6.2. Главный цикл

Любая игра или интерактивная программа на pygame устроена как бесконечный цикл. Каждый проход цикла — один **кадр**. Программа делает 60 кадров в секунду:

```python
while self.running:
    dt = min(clock.tick(60) / 1000.0, 0.1)   # 1. ждём до следующего кадра; dt — прошедшее время в секундах
    for event in pygame.event.get():         # 2. обрабатываем все накопившиеся события
        self._handle(event)                  #    (клики, движения мыши, клавиши, изменение размера окна)
    screen = self.screens[self.active]
    screen.update(dt)                        # 3. продвигаем анимацию на dt секунд
    self.screen.fill(theme.BG)               # 4. заливаем окно белым
    screen.draw(self.screen)                 # 5. рисуем экран заново целиком
    self.lang_button.draw(self.screen)       #    и кнопку языка поверх
    pygame.display.flip()                    # 6. показываем нарисованное
```

Важные следствия:
- **Экран перерисовывается полностью каждый кадр.** Ничего «стирать» не нужно: всё рисуется с нуля по текущему состоянию. Чтобы что-то изменилось на экране, достаточно поменять переменную.
- **`dt` ограничено 0.1 с.** Если программа «подвисла» (например, считала теорию), анимация не прыгнет вперёд рывком.
- Каждый экран обязан иметь четыре метода: `layout`, `handle`, `update`, `draw` (раздел 12.1).

### 6.3. Путь клика мыши

## 7. Физика: `ncorr/physics/neimark.py`

Этот файл — вся модель осциллятора. Он не знает ничего про графику.

### 7.1. Константа `A`

```python
A = 1.0  # критическая скорость a; все величины измеряются в единицах a
```

Порог удара $a$. Все скорости в программе измеряются в единицах $a$, поэтому $a = 1$.

### 7.2. Класс `Params` — параметры осциллятора

```python
class Params:
    def __init__(self, gamma, h):
        self.gamma = float(gamma)   # рост амплитуды за период
        self.h = float(h)           # сила удара (в единицах a, то есть это h/a)
```

Хранит два числа, остальное вычисляется **свойствами** (`@property` — метод, который вызывается без скобок, как обычное поле: `p.s`, а не `p.s()`):

| Свойство | Формула | Смысл |
|---|---|---|
| `s` | $\sqrt{\gamma}$ | во сколько раз растёт скорость за полпериода |
| `delta` | $\ln\gamma / 2\pi$ | коэффициент «антитрения» $\delta$ |
| `lower` | $-\sqrt\gamma\,a$ | нижний край аттрактора |
| `upper` | $a$ | верхний край |
| `branch` | $-a/\sqrt\gamma$ | точка ветвления |

Методы:
- `h_range()` возвращает допустимый диапазон $h/a$ при данном $\gamma$: $(\gamma-1,\ 1+\sqrt\gamma)$ — границы области хаоса.
- `is_chaotic()` проверяет, что параметры внутри области хаоса.
- `__eq__` — два объекта `Params` равны, если равны оба числа. Нужно, чтобы не пересчитывать всё, когда параметры фактически не изменились.
- `__repr__` — как объект печатается в отладке: `Params(gamma=2.618, h=1.618)`.

### 7.3. Пресеты

```python
GOLDEN = (1.0 + math.sqrt(5.0)) / 2.0      # золотое сечение φ ≈ 1.618

PRESETS = {
    "H": Params(GOLDEN ** 2, GOLDEN ** 2 - 1.0),  # γ = φ², h = φ² − 1 = φ
    "E": Params(GOLDEN ** 2, GOLDEN ** 2),        # γ = φ², h = φ²
}
```

Две марковские точки из статьи 1993 года. Значения выражены точно через золотое сечение, а не округлены до 1.618, — иначе марковское разбиение не замкнулось бы точно (раздел 9.6).

Порядок ключей в словаре важен: в таком порядке точки рисуются на плоскости параметров.

### 7.4. Функция `step` — главная формула

```python
def step(y, p):
    """Отображение за полпериода y_n -> y_{n+1}."""
    z = -p.s * y          # через полпериода: скорость сменила знак и выросла в √γ раз
    if z >= A:            # если она не меньше порога...
        z -= p.h          # ...удар уменьшает её на h
    return z
```

Это формула $y_{n+1} = -\sqrt\gamma\,y_n - h\,\theta(-\sqrt\gamma\,y_n - a)$, записанная кодом. Всё остальное в программе строится на ней.

### 7.5. Функция `sequence` — генерация ряда

```python
def sequence(p, n, seed=None, burn=500):
    rng = random.Random(seed)
    y = rng.uniform(p.branch, A)      # случайная стартовая точка внутри аттрактора
    for _ in range(burn):             # 500 «холостых» шагов
        y = step(y, p)
    out = [0.0] * n
    for i in range(n):
        out[i] = y
        y = step(y, p)
    return out
```

Пояснения:
- **Случайный старт** нужен только для того, чтобы не попасть случайно на особую точку (например, на неподвижный ноль). Сам процесс дальше полностью детерминирован.
- **`seed`** — «зерно» генератора случайных чисел. С одним и тем же `seed` старт всегда одинаковый, и программа при каждом запуске показывает один и тот же ряд. В `demo.py` используется `seed=1`.
- **`burn=500`** — первые 500 значений отбрасываются, чтобы процесс «забыл» начальную точку и вышел на стационарный режим.
- Список создаётся сразу нужной длины (`[0.0] * n`) и заполняется — это быстрее, чем многократный `append`.

### 7.6. Функции для непрерывного режима

```python
def shape(u, delta):
    """f(u) = e^{δu}(δ sin u + cos u)"""
    return math.exp(delta * u) * (delta * math.sin(u) + math.cos(u))
```

Скорость в фазе $u$ полупериода при начальной скорости 1. Скорость при начальной скорости $y_n$ равна $y_n \cdot f(u)$.

```python
def shape_table(p, samples):
    d = p.delta
    return [shape((j + 0.5) * math.pi / samples, d) for j in range(samples)]
```

Таблица значений $f$ в `samples` точках полупериода. Точки берутся в **серединах** отрезков ($j + 0.5$), а не на краях — так интегралы в теории и средние в эксперименте считаются одинаково.

```python
def velocity(ys, p, samples):
    f = shape_table(p, samples)
    out = []
    for y in ys:
        out.extend(y * fj for fj in f)
    return out
```

Превращает ряд $y_n$ в непрерывную скорость $v(t)$: каждый $y_n$ даёт `samples` значений. В программе `samples = 16`, то есть шаг по времени $\pi/16$.

### 7.7. Класс `Motion` — движение во времени

Нужен вкладке «Движение осциллятора»: там важно не только знать $y_n$, но и плавно показывать, где находится груз в каждый момент.

```python
mo = nm.Motion(params, v0)   # старт: x = 0, скорость v0
mo.advance(dt)               # продвинуть время на dt; возвращает число ударов за это время
x, v = mo.state()            # текущие координата и скорость
mo.pairs()                   # пары (y_n, y_{n+1}) для графика отображения
mo.on_cross = f              # f(y) вызывается с каждой новой скоростью y_n
twin = nm.Motion.near(mo, 1e-5)  # копия текущего состояния со скоростью больше на 1e-5
```

Устройство:
- Движение хранится как список полупериодов `halves`. Каждый `HalfPeriod` знает свой номер `n` от начала движения, момент начала `t0`, начальную скорость `y`, а после окончания — скорость до удара `before`, после удара `after` и был ли удар `hit`.
- Текущее состояние — последний полупериод и время `s`, прошедшее с его начала. Координата и скорость вычисляются точно: $x = y\,e^{\delta s}\sin s$ (функция `position`), $v = y\,f(s)$ (функция `shape`).
- `advance(dt)` двигает `s`. Если `s` дошло до $\pi$, вызывается `_cross()`: применяется **то же правило `step()`**, что и в остальной программе, и начинается новый полупериод. Поэтому результат не зависит от того, какими кусками продвигать время (это проверяет тест `test_frame_independence`).
- Если $|x|$ или $|v|$ превысили `LIMIT = 10⁴`, ставится флаг `escaped`: движение ушло на бесконечность (например, без ударов).
- Хранится около `HISTORY = 2000` последних полупериодов; старые удаляются пачками, когда их становится в полтора раза больше (удалять по одному из начала списка медленно).
- `on_cross` — необязательная функция, которую `_cross()` вызывает с каждой новой скоростью $y_n$. Через неё тест `test_correlation_from_motion` проверяет, что корреляционная функция скоростей из движения во времени та же, что и у последовательности на вкладке корреляции.
- `Motion.near(other, dv)` — новая траектория, совпадающая с `other` в текущий момент, но со скоростью текущего полупериода больше на `dv`. Номера полупериодов у них общие, поэтому их можно сравнивать по `n`. Так как период движения $\pi$ не зависит от амплитуды, прохождения $x = 0$ у обеих траекторий происходят в одни и те же моменты.
- Нулевая начальная скорость — особый случай: осциллятор покоится в $x = 0$, время просто идёт.

## 8. Эксперимент: `ncorr/physics/correlation.py`

Считает выборочную корреляционную функцию по любому ряду чисел.

```python
class Estimator:
    def __init__(self, data):
        self.data = data
        n = len(data)
        self.mean = sum(data) / n                          # среднее
        self.centered = [x - self.mean for x in data]      # отклонения от среднего
        self.var = sum(x * x for x in self.centered) / n   # дисперсия = R(0)

    def raw(self, k):
        c = self.centered
        n = len(c) - k
        if n <= 0:
            return 0.0
        return sum(a * b for a, b in zip(c, c[k:])) / n    # среднее произведений c_i · c_{i+k}

    def normalized(self, k):
        return self.raw(k) / self.var if self.var > 0 else 0.0
```

Это ровно формула
$$\hat R(k) = \frac{1}{N-k}\sum_{n=1}^{N-k}(y_n - \bar y)(y_{n+k} - \bar y),\qquad \rho(k) = \hat R(k)/D.$$

Идеи:
- Среднее, отклонения и дисперсия считаются **один раз** в конструкторе. Потом каждый сдвиг стоит один проход по списку.
- `zip(c, c[k:])` даёт пары $(c_0, c_k), (c_1, c_{k+1}), \dots$ — это и есть «копия, сдвинутая на $k$».
- Функция считает **один сдвиг за вызов**. Это сделано специально для анимации: каждый шаг считает один столбик, а не все сразу.

Класс не знает, откуда взялись данные: тот же код работает и для $y_n$, и для $v(t)$.

**`Running(kmax)`** — та же функция, но копится на лету, по одному значению (удобно, когда $y_n$ появляются по ходу движения; сейчас используется в тестах):

```python
run = correlation.Running(30)
run.push(y)          # добавить значение: kmax + 1 умножений, память не растёт
run.normalized()     # [R(0)/R(0), R(1)/R(0), ..., R(kmax)/R(0)]
run.moments()        # M[k] = выборочное ⟨y_n y_{n+k}⟩ — для непрерывной C(τ)
run.mean, run.var, run.count
```

Хранятся только суммы $\sum y_n$ и $\sum y_n y_{n-k}$ и последние `kmax + 1` значений. $R(k)$ считается как $M_k - \bar y^2$; на длинной выборке это совпадает с `Estimator` (тест `test_running_estimator`).

## 9. Теория: `ncorr/physics/markov.py`

Самый математический файл. Он вычисляет **точную** корреляционную функцию без генерации случайных чисел — оранжевый пунктир на экране. Если вы не меняете физику, этот файл можно не трогать.

### 9.1. Общая идея

1. Найти точки, которые делят отрезок скоростей $[-\sqrt\gamma, 1]$ на кусочки так, что каждый кусочек отображается целиком на несколько других (**марковское разбиение**).
2. На таком разбиении стационарная плотность вероятности постоянна на каждом кусочке.
3. Корреляцию $\langle y_0 y_k\rangle$ можно получить, $k$ раз применив к функции $y\cdot w(y)$ оператор переноса плотности $P$ (**оператор Перрона–Фробениуса**).
4. Функции, линейные на каждом кусочке, после применения $P$ остаются линейными на каждом кусочке. Значит, достаточно хранить по **два числа** на кусочек — и всё считается точно.

### 9.2. Как хранится функция

Функция, линейная на каждом отрезке $I_i$, хранится двумя списками одной длины:

```
c0[i], c1[i]   →   на отрезке I_i функция равна c0[i] + c1[i] · z
```

Например:
- плотность $w(y)$ (постоянная на отрезках): `c0 = w`, `c1 = 0`;
- функция $y \cdot w(y)$: `c0 = 0`, `c1 = w`.

### 9.3. Класс `MarkovPartition`

```python
class MarkovPartition:
    def __init__(self, points, p, exact):
        self.points = points   # отсортированные точки разбиения
        self.exact = exact     # True — разбиение замкнулось точно
        self.n = len(points) - 1   # число отрезков
        self.maps = []
        for i in range(self.n):
            l, r = points[i], points[i + 1]
            c = -p.h if r <= p.branch + 1e-12 else 0.0     # левее ветвления — удар
            hi = _nearest(points, -p.s * l + c)            # образ левого края (наверху)
            lo = _nearest(points, -p.s * r + c)            # образ правого края (внизу)
            if hi <= lo:
                hi = lo + 1
            slope = -(points[hi] - points[lo]) / (r - l)
            offset = points[hi] - slope * l
            self.maps.append((slope, offset, lo, hi))
```

Для каждого отрезка $[l, r]$ записывается, куда он отображается:
- `lo`, `hi` — номера точек разбиения, между которыми лежит образ. Отрезок переходит на отрезки с номерами `lo, lo+1, …, hi-1`.
- `slope`, `offset` — линейная функция $z = \text{slope}\cdot y + \text{offset}$, переводящая $[l, r]$ ровно на $[\text{points[lo]}, \text{points[hi]}]$ с переворотом (наклон отрицательный).

Почему `slope` вычисляется, а не берётся просто $-\sqrt\gamma$: в приближённом разбиении (раздел 9.6) образ края попадает не точно в точку разбиения, а рядом. Тогда отображение слегка подправляется, чтобы отрезок переходил ровно на целые отрезки и вероятность не «терялась». В точном разбиении `slope` получается ровно $-\sqrt\gamma$.

`1e-12` — допуск на ошибки округления чисел с плавающей точкой.

### 9.4. Метод `transfer` — один шаг оператора $P$

```python
def transfer(self, c0, c1):
    n0 = [0.0] * self.n
    n1 = [0.0] * self.n
    for i, (slope, offset, lo, hi) in enumerate(self.maps):
        a0, a1 = c0[i], c1[i]
        if a0 == 0.0 and a1 == 0.0:
            continue
        k = 1.0 / abs(slope)
        b0 = (a0 - a1 * offset / slope) * k
        b1 = (a1 / slope) * k
        for j in range(lo, hi):
            n0[j] += b0
            n1[j] += b1
    return n0, n1
```

Откуда формулы. На отрезке $i$ функция равна $a_0 + a_1 y$. Точка $y$ переходит в $z = \text{slope}\cdot y + \text{offset}$, то есть $y = (z - \text{offset})/\text{slope}$. Подставляем:
$$a_0 + a_1\frac{z - \text{offset}}{\text{slope}} = \Big(a_0 - a_1\frac{\text{offset}}{\text{slope}}\Big) + \frac{a_1}{\text{slope}}\,z.$$
Плотность при растяжении делится на $|\text{slope}|$ — это множитель `k`. Результат добавляется на все отрезки, куда попадает образ (`for j in range(lo, hi)`). Слагаемые от разных исходных отрезков складываются — это сумма по прообразам в формуле оператора Перрона–Фробениуса.

### 9.5. Методы `stationary` и `moments`

`stationary()` находит стационарную плотность $w$, для которой $Pw = w`:

```python
w = [1.0 / total] * self.n          # старт: равномерная плотность
for _ in range(max_iter):
    pw, _ = self.transfer(w, zero)
    new = [(x + y) * 0.5 for x, y in zip(w, pw)]       # «ленивый» шаг: среднее w и Pw
    mass = sum(x * L for x, L in zip(new, lengths))
    new = [x / mass for x in new]                      # нормировка: полная вероятность = 1
    if max(abs(x - y) for x, y in zip(new, w)) < tol:  # перестало меняться — готово
        return new
    w = new
```

Это **итерационный метод**: многократно применяем $P$, пока плотность не перестанет меняться. «Ленивый» шаг $(w + Pw)/2$ гарантирует сходимость даже там, где процесс «качается» между двумя состояниями (как в нормальном режиме): обычная итерация там прыгала бы туда-обратно бесконечно.

`moments(kmax)` вычисляет $M_k = \langle y_n y_{n+k}\rangle$ для $k = 0..k_{\max}$ и среднее $\langle y\rangle$:

```python
mean = Σ w_i · (r² − l²)/2                 # ∫ y w(y) dy
c0, c1 = 0, w                              # функция y·w(y)
повторить kmax+1 раз:
    M_k = Σ [ c0_i (r² − l²)/2 + c1_i (r³ − l³)/3 ]    # ∫ z · (c0 + c1 z) dz
    c0, c1 = transfer(c0, c1)              # ещё один шаг P
```

Интегралы от линейной функции считаются точно по формулам, без численного интегрирования.

### 9.6. Построение разбиения: `build_partition` и `_orbit_points`

```python
def _orbit_points(p, eps, max_points):
    pts = [p.branch]                       # точка ветвления — всегда точка разбиения
    queue = [A - p.h, p.lower, A]          # стартовые точки: образ ветвления, края
    while queue:
        q = queue.pop()
        q = min(max(q, p.lower), A)        # не выходить за аттрактор
        i = _nearest(pts, q)
        if abs(pts[i] - q) <= eps:         # уже есть такая точка (с точностью eps)
            continue
        bisect.insort(pts, q)              # вставить, сохранив сортировку
        if len(pts) > max_points:
            return None                    # не замкнулось — сдаёмся
        queue.append(step(q, p))           # следующей проверим её образ
    ... (края аттрактора выставляются точно)
    return pts
```

Это ровно то, что описано в книге (с. 76): берём особые точки, применяем к ним отображение, добавляем новые точки, пока новые не перестанут появляться.

`build_partition` пробует разные точности по очереди:

```python
for eps in (1e-9, 2e-4 * span, 1e-3 * span):
    pts = _orbit_points(p, eps, max_points)
    if pts is not None:
        return MarkovPartition(pts, p, exact=(eps == 1e-9))
return MarkovPartition(_orbit_points(p, 3e-3 * span, 10 ** 9), p, exact=False)
```

- $\varepsilon = 10^{-9}$ — фактически точное совпадение. Срабатывает в марковских точках H (2 отрезка) и E (3 отрезка). На экране: «Марковское разбиение: N = 2 (точное)».
- Если точек больше 3000, точность ослабляется: точки ближе $\varepsilon$ считаются совпавшими. Получается приближённое разбиение, обычно на десятки или сотни отрезков: «N = 236 (приближённое)».

Вспомогательная `_nearest(points, x)` находит номер ближайшей к `x` точки в отсортированном списке за $O(\log n)$ с помощью двоичного поиска (`bisect`).

### 9.7. `discrete_theory` и `continuous_theory`

```python
def discrete_theory(p, kmax, partition=None):
    part = partition or build_partition(p)
    m, mean = part.moments(kmax + 1)
    r0 = m[0] - mean * mean                      # дисперсия
    return [(x - mean * mean) / r0 for x in m[:kmax + 1]], part, m, mean
```

Возвращает четыре вещи: нормированную $\rho(k)$, разбиение (для надписи «N = …»), сырые моменты $M_k$ и среднее (они нужны для непрерывной теории).

`continuous_theory(p, samples, lags, moments, mean)` считает $C(\tau)/C(0)$ для $v(t)$ по формуле
$$\langle v(t)v(t+\tau)\rangle = \frac{1}{\pi}\Big[M_m\!\int_0^{\pi-r}\!f(u)f(u+r)\,du + M_{m+1}\!\int_{\pi-r}^{\pi}\!f(u)f(u+r-\pi)\,du\Big],\quad \tau = m\pi + r.$$

В коде сдвиг измеряется в отсчётах: `j = m * samples + r` (`divmod` делит с остатком). Интегралы заменены суммами по тем же точкам `shape_table`, что и в эксперименте:
- `same` — сумма $f[u]\,f[u+r]$, пока сдвинутая точка в том же полупериоде;
- `cross` — сумма $f[u]\,f[u+r-\text{samples}]$, когда она перешла в следующий.

### 10.1. `resources.py` — где лежат файлы

Проблема: в исходниках папка `assets/` лежит рядом с `ncorr/`, а в собранной программе — внутри `_internal/`. Функция `base_dir()` решает это:

```python
def base_dir():
    if getattr(sys, "frozen", False):          # мы внутри собранной PyInstaller программы?
        return getattr(sys, "_MEIPASS", os.path.dirname(sys.executable))
    return os.path.dirname(os.path.dirname(os.path.abspath(__file__)))   # корень проекта

def path(*parts):
    return os.path.join(base_dir(), "assets", *parts)
```

**Всегда** получайте путь к файлам через `res.path(...)`, а не пишите `"assets/..."` вручную — иначе в собранной программе файл не найдётся.

**Кэш** (`_fonts`, `_images`) — словари, где хранятся уже загруженные шрифты и картинки. Загрузка шрифта с диска медленная, а текст рисуется сотни раз за кадр. Поэтому шрифт каждого размера загружается один раз:

```python
def font(size, bold=False, serif=False, italic=False):
    key = (size, bold, serif, italic)
    if key not in _fonts:
        ... выбрать файл DejaVuSans.ttf / DejaVuSerif-Bold.ttf / ...
        _fonts[key] = pygame.font.Font(path("fonts", name), size)
    return _fonts[key]
```

- `image(*parts)` — картинка или `None`, если файла нет. Благодаря `None` отсутствующее фото автора не роняет программу.
- `load_json(*parts)` — читает JSON (для `authors.json`).
- `clear_cache()` — очищает кэш. Нужен, когда pygame перезапускается (в тестах): старые шрифты после `pygame.quit()` становятся недействительными.

Шрифты встроены в программу (DejaVu), а не берутся из системы — так программа выглядит одинаково на любом компьютере и все символы (γ, ⟨⟩, ₙ) гарантированно есть.

## 11. Элементы интерфейса: `ncorr/ui/`

### 11.1. `widgets.py`

**Виджет** — элемент интерфейса: кнопка, ползунок. У каждого есть:
- `rect` — прямоугольник на экране (`pygame.Rect(x, y, ширина, высота)`);
- `visible` — показывать ли;
- `handle(event)` — обработать событие; возвращает `True`, если событие «съедено» этим виджетом (тогда другим оно не передаётся);
- `draw(surf)` — нарисовать себя.

**Функции рисования текста:**

```python
draw_text(surf, text, pos, size, color=FG, anchor="topleft", bold=False, serif=False, italic=False)
```

Рисует строку и возвращает прямоугольник, который она заняла. `anchor` — к какой точке текста привязать `pos`: `"topleft"`, `"center"`, `"midtop"`, `"topright"`, `"midleft"` и т. д. Например, `anchor="center"` ставит центр текста в точку `pos` — так текст центрируется на кнопке.

```python
fit_text(text, size, max_width, **kw)
```

Подбирает размер шрифта: уменьшает `size`, пока текст не влезет в `max_width`. Благодаря этому длинные английские надписи не вылезают за кнопки.

**`Button(label, on_click, font_size)`:**
- `label` — функция, возвращающая текст;
- `on_click` — функция, вызываемая при клике (**колбэк**);
- `selected` — нарисовать как выбранную (чёрная);
- `enabled` — можно ли нажать.

Цвет фона зависит от состояния: обычная, под мышью, нажатая, выбранная.

**`Segmented(options, value, on_change)`** — ряд кнопок, из которых выбрана одна (как «Точка H / Точка E / Свои»):
- `options` — список пар `(значение, функция-надпись)`;
- `value` — текущее значение;
- `on_change(новое_значение)` — вызывается при смене выбора.

Внутри просто список `Button`. Метод `_chooser(v)` создаёт для каждой кнопки свою функцию-обработчик, «запомнившую» своё значение `v` (это называется **замыкание**).

**`Slider(label, vmin, vmax, value, on_change, fmt, log)`:**
- `fmt` — функция, превращающая значение в текст справа (например, `lambda v: f"{v:.3f}"`);
- `log=True` — логарифмическая шкала: середина ползунка соответствует среднему геометрическому, а не арифметическому. Используется для длины выборки (1000…100 000) и скорости (0.25…4);
- `on_change(value, final)` — вызывается при каждом движении; `final=True` — когда кнопку мыши отпустили.

**Зачем `final`.** Пересчёт всей теории при каждом сдвиге ползунка на пиксель тормозил бы. Поэтому во время перетаскивания только обновляются надписи, а настоящий пересчёт делается один раз, когда мышь отпущена.

Методы `_to_frac` и `_from_frac` переводят значение в долю 0…1 длины дорожки и обратно (с учётом логарифмической шкалы).

### 11.2. `plot.py` — оси графиков

**`Axes(rect, xlim, ylim)`** — переводит координаты данных в пиксели.

```python
def px(self, x):   # данные → пиксель по горизонтали
    return self.rect.x + (x - self.x0) / (self.x1 - self.x0) * self.rect.width

def py(self, y):   # данные → пиксель по вертикали (ось y в pygame направлена ВНИЗ)
    return self.rect.bottom - (y - self.y0) / (self.y1 - self.y0) * self.rect.height
```

В pygame координата $y$ растёт вниз, а на графиках — вверх. Поэтому в `py` вычитание из нижнего края.

Остальное:
- `point(x, y)` — оба сразу;
- `data_x(px)` — обратный перевод (из пикселя в данные), нужен для клика мышью;
- `clip_y(y)` — обрезать значение по границам графика;
- `frame(...)` — нарисовать оси, сетку, подписи делений.

Пределы осей (`x0, x1, y0, y1`) можно менять в любой момент — так `demo.py` прокручивает и масштабирует графики.

**`nice_step(span, target)`** выбирает «красивый» шаг делений (1, 2, 2.5, 5, 10, умноженные на степень десяти), чтобы на оси было примерно `target` делений.

**`dashed_polyline(surf, color, points, dash, gap, width)`** рисует пунктирную ломаную. В pygame нет пунктира, поэтому он нарезается вручную: функция идёт вдоль линии и рисует отрезки длиной `dash` с промежутками `gap`. Штрихи продолжаются через изломы, поэтому пунктир ровный.

**`label_box(surf, rect)`** — полупрозрачная белая подложка под надпись поверх графика, чтобы её было видно.

### 11.3. `param_plane.py` — плоскость параметров

Виджет «Область хаоса».

```python
GAMMA_MIN, GAMMA_MAX = 1.05, 4.0

def clamp(gamma, h):
    gamma = min(max(gamma, GAMMA_MIN), GAMMA_MAX)
    lo, hi = nm.Params(gamma, 0).h_range()
    return gamma, min(max(h, lo), hi)
```

`clamp` «прижимает» любую точку внутрь области хаоса. Её используют и плоскость, и ползунки, поэтому выйти из области нельзя никаким способом.

`ParamPlane`:
- `layout(rect)` — создаёт оси с пределами $h/a \in [0;\,3.25]$, $\gamma \in [1;\,4.25]$, оставляя место под подписи.
- `_pick(pos, final)` — переводит позицию мыши в $(\gamma, h)$, прижимает к области и вызывает `on_change(gamma, h, final)`.
- `handle` — нажатие, перетаскивание, отпускание (как у ползунка, с тем же смыслом `final`).
- `draw` рисует по порядку:
  1. область хаоса — многоугольник: вверх по линии $h = \gamma - 1$ и вниз по кривой $h = 1 + \sqrt\gamma$ (по 61 точке);
  2. бежевый треугольник нормального режима ($h < a$);
  3. оси и подписи $\gamma$, $h/a$;
  4. только при `full=True` (рисунок теории): пунктиры $GD$, $HC$, $DE$ и точки $A, B, C, D, G$ — метод `_draw_lines_and_points`;
  5. точки-пресеты H и E;
  6. текущий выбор — синий кружок.

Этот же класс рисует рисунок 3 в теории (`tools/make_figures.py`, с `full=True`). В программе окно маленькое, поэтому там отмечены только H и E.

### 11.4. `phase_portrait.py` — фазовая плоскость

Окно со спиралью. Константы:
- `SAMPLES = 28` — точек кривой на полупериод;
- `TRAIL = 5` — сколько прошлых полупериодов оставлять на экране.

`set_data(params, ys)` готовит данные при смене параметров:
- `self.unit` — таблица точек одного полупериода при начальной скорости 1: $(e^{\delta u}\sin u,\; f(u))$. Траектория полупериода $n$ — это эта же таблица, умноженная на $y_n$. Синусы и экспоненты считаются один раз, а не каждый кадр.
- `xmax`, `vmax` — масштаб осей, чтобы спираль помещалась.

`draw(surf, pos, start)`:
- `pos` — положение точки в полупериодах, дробное (например, 12.4 — сорок процентов тринадцатого полупериода);
- рисует последние `TRAIL` полупериодов. Чем старее, тем светлее серый цвет (`shade`);
- текущий полупериод рисуется только до доли `frac`, и в конце добавляется точная точка — поэтому движение плавное;
- после каждого законченного полупериода проверяет, был ли удар (`z >= A`), и если да — рисует красный вертикальный отрезок от $z$ до $y_{n+1}$;
- синие точки на оси — значения $y_n$; фиолетовая — текущее положение.

`surf.set_clip(r)` ограничивает рисование прямоугольником окна: всё, что вылезло бы за край, просто не рисуется.

### 12.5. `motion.py` — вкладка «Движение осциллятора»

Демонстрация состоит из двух вкладок: «Движение осциллятора» (`motion.py`) и «Корреляционная функция» (`demo.py`, раздел 13). Кнопка «Демонстрация» в меню открывает первую. Переключатель вкладок — общий объект `app.tabs` (`Segmented`), который оба экрана кладут первым в свой список `widgets`; место под него каждый экран задаёт полем `tabs_rect` (верх панели справа), а `App._layout` ставит переключатель туда, куда скажет активный экран — так же, как кнопку языка (раздел 14.1).

Часть с движением — А. С. Григорьева. Первоначально была сделана как веб-страница (репозиторий `github.com/falsealarm478/neimark-oscillator`); здесь перенесена в приложение на pygame с той же физикой. К ней добавлены две близкие траектории — чтобы на этой же вкладке были видны механизм появления случайности и точка бифуркации.

**Что на экране** (слева три ряда, справа панель):
1. Полоса с осциллятором: стенка, пружина, груз, стрелка скорости, вспышка при ударе (`flash` гаснет за ~0.5 с). Контурный бирюзовый квадрат — груз второй траектории. Над полосой — легенда цветов.
2. Фазовая траектория $(x, v)$ и скорость $v(t)$ с **общей вертикальной шкалой**; пунктир-проекция соединяет текущие точки (`_draw_projection`). Вторая траектория — бирюзовым.
3. Отображение за полпериода (ветви, $y^*$, аттрактор, пары $(y_n, y_{n+1})$) и «Две траектории» (`_draw_twins`): сверху последние `TRACK = 40` значений $y_n$ обеих траекторий и уровень $y^*$, снизу $\lg|\Delta y_n|$ и прямая $\varepsilon\gamma^{n/2}$, подпись «разошлись через … (оценка …)».

**Константы** в начале файла:

| Константа | Смысл |
|---|---|
| `PHASE_TRAIL = 24` | сколько полупериодов оставлять в следе на фазовой плоскости |
| `TIME_WINDOW = 8` | сколько полупериодов видно на графике $v(t)$ |
| `CURVE_SAMPLES = 40` | точек кривой на полупериод |
| `FLASH_DECAY = 1.8` | скорость угасания вспышки удара |
| `TRACK = 40` | сколько последних $y_n$ на графике двух траекторий |
| `SCENARIOS` | сценарии: параметры и начальная скорость |
| `TWINS` | варианты $\varepsilon$: $10^{-2}, 10^{-5}, 10^{-8}$ |

**Как рисуется траектория.** Точки траектории не хранятся. Для каждого полупериода из `motion.halves` функция `curve(half, delta, upto)` заново вычисляет точки по точной формуле. Для текущего полупериода — только до текущего момента `s`.

**Две траектории.** `_restart_twin()` создаёт `self.twin = Motion.near(self.motion, ε)` — копию текущего состояния со скоростью больше на $\varepsilon$ — и запоминает номер полупериода `twin_start`. Вызывается при «Заново» и при выборе $\varepsilon$ (поэтому опыт с расхождением можно повторить в любой момент). `_record(first)` после каждого продвижения:
- ищет `split_n` — первый полупериод, в конце которого одна траектория получила удар, а другая нет (`a.hit != b.hit`): это момент, когда разница дошла до точки ветвления $y^*$;
- дописывает в `self.track` тройки `(n, yₙ, yₙ второй траектории)` для графика.

Полупериоды двух траекторий сопоставляются по номеру `n` (поле `HalfPeriod.n`), метод `_half(mo, n)`. Пока `split_n` не найден, `_advance` двигает время кусками по 500 полупериодов: иначе на большой скорости момент расхождения мог бы выпасть из хранимой истории (`HISTORY = 2000`).

Оценка в подписи: $\ln(1/\varepsilon)/\ln\sqrt\gamma$. Для точки H программа показывает 12, 25 и 40 полупериодов при оценках 9.6, 23.9 и 38.3 (тест `test_nearby_trajectory`).

**Масштаб** `self.ext` — половина размаха осей. Он вычисляется каждый кадр в `update` по последним полупериодам обеих траекторий, но **только растёт** во время опыта (чтобы графики не «прыгали»), а сбрасывается в `_reset`.

**Управление** (методы):

| Метод | Кнопка / событие |
|---|---|
| `_set_scenario(name)` | кнопки сценариев; выставляет параметры и ползунки, начинает заново и запускает |
| `_on_gamma`, `_on_h`, `_on_v0` | ползунки; любой сдвиг начинает опыт заново, сценарий сбрасывается в «свой» |

## 13. Вкладка «Корреляционная функция»: `demo.py`

Самый большой и самый важный файл. Разберём его по частям.

### 13.1. Константы

```python
S = 16              # отсчётов v(t) на полпериод
TAU_STEP = 2        # шаг сдвига для v(t), в отсчётах: 2/16 полупериода = π/8
KMAX = 30           # сколько сдвигов строить для y_n (k = 0..30)
C_STEPS = 48        # сколько сдвигов для v(t): 48 · π/8 = 6π
CONT_HALF = 20000   # по скольким полупериодам считать v(t) (320 000 отсчётов)
CURSOR_SPEED = 1.5  # скорость точки на фазовой плоскости, полупериодов в секунду
CURSOR_SPAN = 40    # точка обходит не больше 40 полупериодов
SHIFT_END, PRODUCT_END = 0.45, 0.7   # тайминг шага анимации (раздел 13.4)
```

Это главные «ручки» экрана. Меняя их, можно управлять поведением, не трогая остальной код.

`ease(x)` — функция плавности $3x^2 - 2x^3$: движение начинается и заканчивается плавно, а не рывком.

`draw_legend(...)` — рисует строку легенды («▪ эксперимент - - теория») справа на белой подложке.

### 13.2. Состояние экрана (поля объекта)

| Поле | Что хранит |

| `speed` | множитель скорости анимации |
| `seed` | зерно генератора (1) |

| `unit` | отсчётов на один полупериод: 1 для $y_n$, 16 для $v(t)$ |
| `lags` | список сдвигов: `[0, 1, …, 30]` или `[0, 2, 4, …, 96]` (в отсчётах) |

| `sigma`, `dev_max`, `lo`, `hi` | масштабы для графиков |

### 13.3. Пересчёт данных: `_recompute`

Вызывается при запуске и при любой смене режима, параметров или длины выборки.

```python
def _recompute(self):
    p = self.params
    self.ys = nm.sequence(p, int(self.n_samples), seed=self.seed)   # 1. ряд
    theory, part, moments, mean = markov.discrete_theory(p, KMAX)  # 2. теория для y_n
    self.partition = part
    if self.mode == "d":                                           # 3а. режим y_n
        self.unit = 1
        self.data = self.ys
        self.lags = list(range(KMAX + 1))
        self.theory = theory
    else:                                                          # 3б. режим v(t)
        self.unit = S
        self.data = nm.velocity(self.ys[:CONT_HALF], p, S)
        self.lags = [i * TAU_STEP for i in range(C_STEPS + 1)]
        self.theory = markov.continuous_theory(p, S, self.lags[-1], moments, mean)
    self.est = correlation.Estimator(self.data)                    # 4. эксперимент
    self.portrait.set_data(p, self.ys)                             # 5. фазовая плоскость
    ... масштабы графиков
    self.values = {}                                               # 6. сбросить кэш
    self._clamp_view()
    self._reset()                                                  # 7. начать построение заново
```

Обратите внимание: сам эксперимент здесь **не** считается — только готовится `Estimator`. Значения считаются лениво, по одному, когда нужны (`_value`).

```python
def _value(self, lag):
    if lag not in self.values:
        self.values[lag] = self.est.normalized(lag)
    return self.values[lag]
```

Каждое значение считается один раз и запоминается. При перерисовке каждый кадр берётся из кэша.

### 13.4. Анимация шага

Один шаг построения столбика — это переменная `phase`, растущая от 0 до 1:

```
phase:  0 ─────────── 0.45 ──────── 0.70 ─────────── 1.0
        │  копия      │ появляются   │  растёт        │
        │  сдвигается │ произведения │  столбик       │ шаг закончен
```

Код в `update(dt)`:

```python
self.phase += dt * self.speed * 1.2          # при скорости ×1 шаг длится 1/1.2 ≈ 0.83 с
target = self.lags[self.built]
self.shift = self.shift_from + (target - self.shift_from) * ease(self.phase / SHIFT_END)
if self.phase >= 1.0:
    self._finish_step()
```

- `shift` плавно движется от старого сдвига к новому за первые 45% шага. `ease(...)` обрезает аргумент до 1, поэтому после 0.45 сдвиг стоит на месте.
- `current_lag()` возвращает видимость произведений: от 0 до 1 между 0.45 и 0.70.
- `_draw_correlation` рисует растущий столбик: `value * grow`, где `grow` растёт от 0 до 1 между 0.70 и 1.0.

Управляющие методы:

| Метод | Кнопка | Что делает |
|---|---|---|
| `_begin_step()` | | начинает шаг: считает значение, ставит `phase = 0` |
| `_finish_step()` | | заканчивает: `phase = None`, `built += 1` |
| `_step_click()` | «Шаг», → | если шаг идёт — мгновенно закончить; иначе начать новый |
| `_toggle_run()` | «Пуск/Пауза», пробел | включить/выключить автоматический режим; если всё построено — начать заново |
| `_reset()` | «Заново» | всё обнулить |
| `_build_all()` | «Построить всё» | включить `filling` |

В режиме `running` после окончания шага `update` сразу начинает следующий.

В режиме `filling` анимации нет: каждый кадр считается столько столбиков, сколько успевает за 30 мс:

```python
start = time.perf_counter()
while self.built < len(self.lags) and time.perf_counter() - start < 0.03:
    self._value(self.lags[self.built])
    self.built += 1
```

Так окно не зависает даже в непрерывном режиме, где один столбик считается около 40 мс: столбики появляются быстро один за другим.

### 13.5. Точка на фазовой плоскости

```python
def _cursor_range(self):
    start, length = self.view[self.mode]
    first = start // self.unit                              # первый видимый полупериод
    span = max(2, min(length // self.unit, CURSOR_SPAN))
    return first, min(first + span, len(self.ys) - 2)
```

В начале `update` курсор сдвигается на `dt * CURSOR_SPEED` полупериодов. Если он вышел за видимую часть, возвращается в её начало. Поэтому точка всегда бегает по тому куску ряда, который сейчас виден на графике.

`_draw_cursor` отмечает это место на первом графике:
- в режиме $y_n$ — фиолетовое кольцо вокруг значения номер `int(cursor)`;
- в режиме $v(t)$ — вертикальная линия и точка на кривой. Значение скорости вычисляется точно: $y_n \cdot f(u)$ при $u = \text{дробная часть} \cdot \pi$.

### 13.6. Смена параметров

Три источника — пресеты, ползунки, плоскость — сходятся в двух методах:

```
кнопка «Точка H/E» ──► _set_preset ──┐
ползунок γ ──────────► _on_gamma ────┤
ползунок h ──────────► _on_h ────────┼──► _show_params(g, h)   обновить ползунки, плоскость, переключатель
плоскость ───────────► _on_plane ────┘         │
                                               └─ если final ──► _apply(g, h) ──► _recompute()
```

- `_show_params` синхронизирует всё видимое. Важная деталь: диапазон ползунка $h$ меняется вместе с $\gamma$ (`set_range`), потому что допустимые $h$ зависят от $\gamma$. Ещё он определяет, совпадают ли параметры с пресетом, и подсвечивает «Точка H», «Точка E» или «Свои».
- `_apply` создаёт новые `Params` и пересчитывает данные, только если параметры реально изменились. Для пресетов берётся сам объект из `PRESETS` с точными значениями (через золотое сечение), а не округлённые числа с ползунка.

Ползунок длины выборки (`_on_n`) округляет значение до сотен и пересчитывает только при отпускании мыши.

### 13.7. Окно просмотра, масштаб и прокрутка

`view[mode] = [начало, длина]` — какие отсчёты видны на графиках 1–3.

- **Колесо мыши** (`handle`, `MOUSEWHEEL`): длина умножается на $1.25^{\pm1}$. Начало сдвигается так, чтобы точка под мышью осталась на месте (`anchor` — доля ширины, где мышь).
- **Перетаскивание**: при нажатии запоминается `_pan = (x мыши, начало)`; при движении начало сдвигается на смещение мыши, переведённое в отсчёты (`per_px`).
- `_clamp_view` держит окно в допустимых пределах: длина 10…2000 значений (или 2…200 полупериодов для $v(t)$), и справа должно оставаться место для сдвинутой копии.

Клавиши: пробел — «Пуск/Пауза», стрелка вправо — «Шаг».

### 13.8. Раскладка `layout`

Экран делится на две части:
- справа панель шириной `max(27% окна, 300 пикселей)`;
- слева четыре графика.

**Правая панель** заполняется с двух концов:
- **сверху вниз:** «Процесс» и переключатель режимов, «Параметры», пресеты, ползунки $\gamma$ и $h$;
- **снизу вверх:** «English» и «Назад», четыре строки информации, «Построить всё», ряд «Пуск / Шаг / Заново», ползунки скорости и длины выборки, заголовок «Построение».

Что осталось между ними, отдаётся двум маленьким окнам — плоскости параметров и фазовой плоскости, бок о бок. Если места меньше `7u` (очень маленькое окно), они скрываются. Так панель всегда влезает в окно.

`self.lang_rect` — место для кнопки языка в панели. `App` читает это поле и ставит туда общую кнопку языка.

**Графики слева** делят высоту в пропорции `weights = (1.0, 1.0, 1.15, 1.4)`: нижний график корреляции самый высокий. Над каждым — строка заголовка, под каждым — строка подписей делений.

### 13.9. Рисование

`draw(surf)` по порядку:
1. фон и рамка панели;
2. заголовки разделов панели (у двух маленьких окон — одним размером шрифта);
3. все виджеты (`super().draw`);
4. фазовая плоскость;
5. четыре строки информации (`_draw_info`);
6. графики 1–3 (`_draw_process`);
7. график 4 (`_draw_correlation`);
8. подсказка «колесо мыши — масштаб…», если мышь над графиками.

**`_draw_series(surf, ax, values, offset, first, last, color, normalize, stems)`** — общая функция рисования ряда. Значение номер `i` рисуется в позиции `i − offset`. С `offset = shift` получается сдвинутая копия. Варианты:
- режим $y_n$ со `stems=True` — «палочки» от нуля с точкой на конце; если точек больше 150, без кружков;
- режим $y_n$ со `stems=False` — только точки (на графике наложения);
- режим $v(t)$ — сплошная линия;
- `normalize=True` — значения в виде отклонений от среднего, делённых на $\sigma$ (для графика наложения).

**`_draw_process`** рисует три верхних графика:
1. исходный ряд, пунктир среднего, фиолетовая отметка курсора;
2. сдвинутая копия (синяя) и стрелка сдвига (`_draw_shift_arrow`);
3. наложение: цветные столбики произведений $c_i c_{i+k}/D$, поверх — обе нормированные реализации, легенда и подпись со средним.

Цветные столбики рисуются на отдельном прозрачном слое (`pygame.SRCALPHA`), который потом накладывается с нужной прозрачностью `alpha` — так они плавно проявляются. Если отсчётов больше, чем пикселей, рисуется каждый `step`-й — экономия времени.

**`_draw_correlation`** рисует нижний график:
- серые столбики для `lags[:built]`;
- растущий синий столбик текущего шага и вертикальная линия текущего сдвига;
- оранжевый пунктир теории: в режиме $y_n$ — с кружками в целых $k$, в режиме $v(t)$ — сплошной пунктирной кривой по всем отсчётам;
- легенда.

**`_draw_info`** выводит четыре строки:
- текущее $\rho$ и теорию;
- среднее, дисперсию, $\delta$;
- разбиение;
- границы аттрактора.

`_fmt_lag` превращает сдвиг в текст: `5` для $y_n$ или `1.5π` для $v(t)$.

### 13.10. `test_setup`

Служебный метод для автоматической проверки и скриншотов: сразу переключает режим и пресет, строит всё или делает заданное число шагов. Вызывается из `main.py` при аргументах `--mode`, `--preset`, `--build`, `--steps`.

## 14. Окно и точка входа: `app.py`, `main.py`

### 14.1. `app.py` — класс `App`

**Конструктор** делает по порядку:
1. `_dpi_aware()` — сообщает Windows, что программа сама учитывает масштаб экрана. Без этого при масштабе 125–150% Windows растягивает окно, и картинка становится размытой.
2. Переменные окружения SDL:
   - `SDL_VIDEO_CENTERED=1` — окно по центру экрана;
   - на Linux `SDL_FRAMEBUFFER_ACCELERATION=0` — вывод без OpenGL. На некоторых системах (виртуальные машины, старые драйверы) OpenGL сломан, и программа падала бы при запуске. Для 2D-графики программный вывод достаточно быстр.
3. Инициализация pygame (только `display` и `font`, без звука — он не нужен и на некоторых системах выдаёт ошибки).
4. Размер окна: если не задан, 90% ширины и 85% высоты экрана, но не меньше 1024×640.
5. Окно с флагом `RESIZABLE` (можно менять размер), иконка, заголовок.
6. Общая кнопка языка и все пять экранов.

Методы:

| Метод | Что делает |
|---|---|
| `show(name)` | сделать экран активным, отметить его на переключателе вкладок (для `motion` и `demo`), вызвать его `enter()`, переразложить |
| `quit()` | выйти из главного цикла (кнопка «Выход») |
| `toggle_fullscreen()` | F11: переключить полноэкранный режим, запомнив размер окна |
| `_layout()` | вызвать `layout` у всех экранов, поставить кнопку языка (туда, куда скажет экран через `lang_rect`, иначе в левый нижний угол) и переключатель вкладок демонстрации (по `tabs_rect` активного экрана) |
| `_switch_tab(name)` | переключатель вкладок: перед переходом на корреляцию вызывает `motion.sync_correlation()`, затем `show(name)` |
| `_toggle_lang()` | переключить язык и заголовок окна |
| `_handle(event)` | разобрать событие (раздел 6.3) |
| `run(frames, screenshot)` | главный цикл (раздел 6.2) |

Обработка клавиш в `_handle`:
- **F11** — полный экран;
- **Escape** — выйти из полного экрана, а если окно и так обычное — вернуться в меню.

Параметры `run(frames=…, screenshot=…)` нужны для проверки: программа отрисует заданное число кадров, сохранит скриншот и закроется. Так собранную программу можно проверить без человека — именно это делает `build.py --check`.

### 14.2. `main.py` — аргументы командной строки

## 15. Тесты

Тесты — код, который проверяет код. Запуск:

```bash
.venv/Scripts/python tools/build.py test
```

Или напрямую:

```bash
.venv/Scripts/python -m unittest discover -s tests -t .
```

Результат `OK` — всё в порядке. `FAILED` — что-то сломано; выше будет написано, какой тест и почему.

### 15.1. `tests/test_physics.py`

| Тест | Что проверяет |
|---|---|
| `test_attractor_bounds` | все $y_n$ лежат в $[-\sqrt\gamma,\ 1]$ |
| `test_sign_pattern` | после положительного $y_n$ всегда отрицательное; два отрицательных подряд бывают только после удара; в нормальном режиме знак чередуется строго |
| `test_velocity_continuity` | в конце полупериода $f(\pi) = -\sqrt\gamma$ |
| `test_crossings_follow_the_map` | движение во времени (`Motion`) даёт ту же последовательность $y_n$, что и `step()` |
| `test_frame_independence` | результат `Motion` не зависит от того, какими шагами продвигать время |
| `test_kick_jump` | удар уменьшает скорость ровно на $h$ и в аномальном режиме может её развернуть |
| `test_escape_without_kicks` | без ударов движение уходит на бесконечность и помечается `escaped` |
| `test_nearby_trajectory` | две траектории с разницей $\varepsilon$: пока они на одной ветви, разница растёт ровно как $\varepsilon\gamma^{n/2}$; расходятся они примерно через $\ln(1/\varepsilon)/\ln\sqrt\gamma$ полупериодов |
| `test_markov_points_from_paper` | в точке H разбиение точное из 2 отрезков, в точке E — из 3, и ноль — точка разбиения (как в статье) |
| `test_density_normalized` | полная вероятность стационарной плотности равна 1 |
| `test_point_h` | теория совпадает с экспериментом (200 000 значений) в точке H — пунктир рис. 5 статьи |
| `test_point_e` | в точке E $\rho(1) = \rho(2) \approx -0.118$, $\rho(3) \approx 0.146$ (сплошная кривая рис. 5) и совпадение с экспериментом |
| `test_approximate_partition` | теория совпадает с экспериментом при произвольных параметрах |
| `test_running_estimator` | накопление на лету (`Running`) даёт то же, что `Estimator` по готовой выборке |
| `test_correlation_from_motion` | связь вкладок: $R(k)$ и $C(\tau)$ по $y_n$ из движения во времени (60 000 полупериодов) совпадают с теорией |

Совпадение проверяется с допуском (`delta=0.006`): эксперимент на конечной выборке всегда немного отличается от теории.

### 15.2. `tests/test_ui_smoke.py`

Прогоняет интерфейс без окна. `SDL_VIDEODRIVER=dummy` — pygame рисует в память, ничего не показывая. События мыши подделываются функциями `click` и `drag`, кадры прокручиваются функцией `frames`.

| Тест | Что проверяет |
|---|---|
| `test_all_screens_and_language` | все экраны рисуются на обоих языках; кнопка языка переключает |
| `test_menu_buttons` | кнопки меню ведут на нужные экраны |
| `test_demo_interaction` | «Шаг», «Пуск/Пауза», все ползунки, клик вне области хаоса (точка прижимается к границе), ползунок выборки (до 1000), все пресеты в обоих режимах с «Построить всё», колесо мыши, перетаскивание, «Заново», «Назад» |
| `test_motion_interaction` | вкладка движения: все сценарии, ползунки, «Шаг π», переключатели, уход на бесконечность без ударов, все $\varepsilon$ и расхождение близких траекторий |
| `test_tabs` | «Демонстрация» открывает вкладку движения; переключатель ведёт на корреляцию и обратно; параметры передаются, только если их меняли на вкладке движения |
| `test_resize` | обе вкладки рисуются при размерах 1024×640, 1920×1080, 2560×1440 |

«Smoke test» (дымовой тест) — тест «включили и посмотрели, не пошёл ли дым»: он не проверяет картинку, но ловит падения и ошибки.

### 15.3. Как добавить свой тест

Добавьте метод, имя которого начинается с `test_`, в класс в одном из файлов:

```python
def test_my_check(self):
    p = nm.Params(2.0, 1.5)
    ys = nm.sequence(p, 1000, seed=1)
    self.assertTrue(all(y <= 1.0 + 1e-9 for y in ys))
```

`unittest` найдёт и запустит его автоматически.

## 16. Рецепты: как сделать типичные изменения

После любого рецепта: проверьте `python main.py`, прогоните тесты, соберите архивы (раздел 3).

### 16.1. Поменять или перевести надпись

Найдите надпись в `ncorr/i18n.py` (поиск по тексту) и поправьте пару `("русский", "english")`. Ключ не трогайте — по нему надпись ищется в коде.

Новая надпись:
1. Добавьте строку в `STRINGS`: `"my_key": ("Текст", "Text"),`.
2. Используйте в коде: `t("my_key")` или в виджете `lambda: t("my_key")`.

Если забыть добавить ключ, программа упадёт с `KeyError: 'my_key'`.

### 16.2. Поменять цвет

Поменяйте значение в `ncorr/theme.py`. Например, сделать теоретическую кривую красной:

```python
THEORY = (200, 0, 0)
```

Цвет поменяется везде, где он используется.

### 16.3. Авторы, руководитель, фото

1. Отредактируйте `assets/authors.json` (кодировка UTF-8).
2. Фото положите в `assets/authors/`, например `assets/authors/ivanov.jpg`, и впишите имя файла: `"photo": "ivanov.jpg"`. Подходят JPG и PNG; удобная пропорция — 3:4 (портрет).
3. Третьего автора добавьте ещё одним элементом в список `authors` — колонки перестроятся сами.

Проверка: `python main.py --screen authors`.

### 16.4. Поменять логотипы

Замените файлы `assets/img/msu_logo.png` (слева, эмблема МГУ) и `assets/img/cmc_logo.png` (справа, логотип ВМК), сохранив имена. Пропорции сохраняются автоматически. `cmc_logo.png` также используется как иконка окна.

### 16.5. Сколько сдвигов строить

`KMAX` в начале `demo.py` — для ряда $y_n$. Для $v(t)$ — `C_STEPS` (число шагов) и `TAU_STEP` (размер шага в отсчётах, шаг по времени = `TAU_STEP/16 · π`).

### 16.6. Длина выборки по умолчанию, скорость анимации

В `DemoScreen.__init__`:

```python
self.n_samples = 50000   # длина выборки при запуске
self.speed = 1.0         # скорость анимации при запуске
```

Пределы ползунков задаются при их создании там же: `Slider(..., 1000, 100000, ...)` и `Slider(..., 0.25, 4.0, ...)`.

Базовая длительность шага — множитель `1.2` в `update`: `self.phase += dt * self.speed * 1.2`. Меньше — медленнее.

### 16.7. Какой пресет открывается при запуске

В `DemoScreen.__init__` строка `self.params = nm.PRESETS["H"]` и третий аргумент `"H"` в `self.preset_sel = Segmented(...)`. Поменяйте оба на `"E"`. В `ParamPlane.__init__` также стоит начальная точка H — её стоит поменять тоже, хотя она перезапишется при первом изменении.

### 16.8. Добавить новую точку-пресет

1. В `neimark.py` в `PRESETS` добавьте: `"G": Params(2.0, 1.0),`.
2. В `i18n.py` добавьте надпись: `"preset_G": ("Точка G", "Point G"),`.
3. В `demo.py` в `self.preset_sel` добавьте вариант: `("G", lambda: t("preset_G")),` перед `"custom"`.
4. В `param_plane.py` в словарь `offsets` добавьте, где рисовать подпись: `"G": ("bottomright", (-5, -1)),`. Иначе будет `KeyError`.

Осторожно с точкой G: там процесс неэргодичен, и корреляция за полпериода не затухает.

### 16.9. Добавить кнопку

Пример: кнопка «Случайный старт», которая меняет `seed` и пересчитывает ряд.

1. Надпись в `i18n.py`: `"reseed": ("Новый ряд", "New series"),`.
2. В `DemoScreen.__init__`:
   ```python
   self.b_reseed = Button(lambda: t("reseed"), self._reseed)
   ```
   и добавьте `self.b_reseed` в список `self.widgets` — иначе кнопка не будет ни рисоваться, ни нажиматься.
3. Метод:
   ```python
   def _reseed(self):
       self.seed += 1
       self._recompute()
   ```
4. В `layout` задайте место и шрифт, например рядом с «Построить всё»:
   ```python
   self.b_all.rect = pygame.Rect(x, y2, width // 2 - 3, row)
   self.b_reseed.rect = pygame.Rect(x + width // 2 + 3, y2, width - width // 2 - 3, row)
   self.b_reseed.font_size = fs
   ```

### 16.10. Добавить ползунок

Так же, как кнопку, но через `Slider`:

```python
self.s_my = Slider(lambda: t("my_label"), 0.0, 10.0, 5.0, self._on_my, fmt=lambda v: f"{v:.1f}")

def _on_my(self, v, final):
    self.my_value = v
    if final:
        ...  # тяжёлый пересчёт только при отпускании
```

В `layout`: `self.s_my.layout((x, y, width, slider_h))` и сдвиньте `y`/`y2` на `slider_h + gap`. Не забудьте добавить в `self.widgets` и выставить `font_size`.

### 16.11. Добавить новый экран

1. Создайте `ncorr/screens/my_screen.py`:
   ```python
   import pygame
   from .. import theme
   from ..i18n import t
   from ..ui.widgets import Button, draw_text
   from .base import Screen

   class MyScreen(Screen):
       def __init__(self, app):
           super().__init__(app)
           self.back = Button(lambda: t("back"), lambda: app.show("menu"))
           self.widgets = [self.back]

       def layout(self, w, h):
           self.back.rect = pygame.Rect(w - int(w * 0.18), h - int(h * 0.1), int(w * 0.14), int(h * 0.06))

       def draw(self, surf):
           w, h = surf.get_size()
           draw_text(surf, "Привет", (w // 2, h // 2), 40, anchor="center")
           super().draw(surf)
   ```
2. В `app.py` импортируйте его и добавьте в словарь `self.screens`: `"my": MyScreen(self),`.
3. В `menu.py` добавьте кнопку: `Button(lambda: t("my"), lambda: app.show("my")),` и надпись `"my"` в `i18n.py`.
4. Чтобы открывать его из командной строки, добавьте `"my"` в `choices` аргумента `--screen` в `main.py`.

### 16.12. Поменять физику (другое отображение)

Всё начинается с `step()` в `neimark.py`. Если поменять правило там:
- генерация ряда, фазовая плоскость (частично) и эксперимент подстроятся сами;
- **теория** в `markov.py` построена именно для кусочно-линейного отображения с одной точкой ветвления. Для другого отображения её придётся переписать, иначе оранжевый пунктир будет неверным;
- **фазовая плоскость** рисует траекторию по формулам этого осциллятора (`shape`); при другой модели её тоже нужно поменять;
- **тесты** в `test_physics.py` проверяют конкретные числа из статьи и упадут — это ожидаемо.

### 16.13. Поменять размер окна при запуске

В `app.py`, в конструкторе `App`:

```python
size = (max(MIN_SIZE[0], int(desktop[0] * 0.9)), max(MIN_SIZE[1], int(desktop[1] * 0.85)))
```

`0.9` и `0.85` — доли ширины и высоты экрана. Минимальный размер — `MIN_SIZE`. Чтобы запускаться сразу во весь экран, проще передать `fullscreen=True` в `App` в `main.py`.

### 16.14. Изменить шрифт всей программы

Положите `.ttf` в `assets/fonts/` и поправьте имена файлов в `resources.font()`. Нужны начертания: обычное, жирное, курсив — для гротеска и для антиквы (у нас DejaVuSans и DejaVuSerif). Проверьте, что в новом шрифте есть кириллица и символы γ, δ, τ, π, ⟨, ⟩, ₙ, ₖ, ₊, −, √.

### 16.15. Изменить README внутри архива

Текст в словаре `README` в `tools/package.py`, отдельно для Windows и Linux.

## 17. Теория (Typst) и рисунки

### 17.1. Как устроено

```
theory/theory_ru.typ ─┐                       ┌─► theory/theory_ru.pdf        (кладётся в архив)
theory/theory_en.typ ─┼─► tools/build_theory ─┤
theory/style.typ ─────┤                       └─► assets/theory/ru/page-NN.png (показывается в программе)
theory/fig_*.png ─────┘
       ▲
tools/make_figures.py (рисует fig_phase, fig_map, fig_plane)
```

Команда `python tools/build.py theory` делает обе стадии: рисунки и вёрстку.

### 17.2. Язык Typst — самое нужное

Typst похож на Markdown с формулами как в LaTeX.

| Что | Пишется |
|---|---|
| заголовок раздела | `= Название` |
| подраздел | `== Название` |
| жирный | `*текст*` |
| курсив | `_текст_` |
| термин (жирный курсив, наша функция) | `#term[текст]` |
| формула в строке | `$x^2 + y_n$` |
| формула отдельной строкой с номером | `$ x^2 + y_n $` (пробелы внутри `$ ... $`) |
| метка формулы и ссылка на неё | `$ ... $ <map>` и `(@map)` |
| нумерованный список | строки с `+ ` |
| маркированный список | строки с `- ` |
| рисунок | `#figure(image("fig_map.png", width: 56%), caption: [Подпись])` |
| таблица | `#table(columns: (auto, 1fr), [ячейка], [ячейка], ...)` |

Формулы:
- греческие буквы словами: `gamma`, `delta`, `tau`, `pi`;
- корень: `sqrt(gamma)`;
- индекс из нескольких символов — в скобках: `y_(n+1)`;
- дробь: `a/b` или `1/(N-k)`;
- сумма: `sum_(n=1)^(N-k)`;
- интеграл: `integral_0^pi`;
- точка над буквой: `dot(x)`, две точки: `dot.double(x)`;
- текст внутри формулы — в кавычках: `"при"`;
- перенос длинной формулы: `\` в конце строки, выравнивание по `&`.

**Ловушка:** `//` в Typst начинает комментарий, всё после него в строке пропадает. В списке литературы двойную косую черту пишите как `\/\/`. Внутри формулы `/` превращается в дробь; чтобы получить просто косую черту, пишите `h\/a`.

### 17.3. `style.typ`

- `target` — переменная, которую передаёт `build_theory.py`: `"pdf"` или `"png"`.
- Для PDF — страницы A4 с номерами.
- Для PNG — узкие страницы 17×24 см без номеров, чтобы удобно читать на экране.
- Там же оформление заголовков, таблиц, подписей рисунков и функции `title` и `term`.

### 17.4. `tools/build_theory.py`

Для каждого языка дважды вызывает `typst.compile`:
- в PDF (`sys_inputs={"target": "pdf"}`);
- в PNG с разрешением 200 точек на дюйм (`target: png`). Старые PNG перед этим удаляются, новые сохраняются как `page-01.png`, `page-02.png`, …

Если в Typst-файле ошибка, команда упадёт с сообщением, где она.

### 17.5. `tools/make_figures.py`

Рисует три рисунка средствами pygame, без окна:
- `fig_phase()` — спираль с двумя ударами. Старт $y_1 = -0.7$ подобран так, чтобы первый удар разворачивал скорость, а второй нет. Два удара рисуются чуть по разные стороны оси, чтобы не слились;
- `fig_map()` — график отображения в точке H;
- `fig_plane()` — плоскость параметров, нарисованная классом `ParamPlane` из программы.

Подписи на рисунках только символьные ($x$, $v$, $a$, $h$, $y^*$), поэтому рисунки общие для обоих языков.

## 18. Упаковка: PyInstaller, Docker, архивы

### 18.1. Что делает PyInstaller

PyInstaller находит все модули, которые импортирует программа, и складывает в одну папку:
- копию интерпретатора Python (`python314.dll` или `libpython3.12.so`);
- библиотеки (pygame, SDL);
- наш код (в сжатом виде);
- файлы `assets/`;
- запускающий `.exe` (или бинарник на Linux).

Результат — `dist/windows/NeimarkCorrelation/`: `NeimarkCorrelation.exe` и папка `_internal`. Запускать нужно именно `.exe`, и папку нельзя разделять.

Это режим **onedir** (папка). Есть ещё **onefile** (один `.exe`), но он при каждом запуске распаковывается во временную папку — медленнее стартует и чаще вызывает ложные срабатывания антивирусов. Проекты на сайте используют оба варианта.

### 18.2. `build/neimark.spec`

Файл настроек PyInstaller — это Python-код:

```python
a = Analysis(
    [os.path.join(ROOT, "main.py")],                     # с чего начинать поиск импортов
    pathex=[ROOT],
    datas=[(os.path.join(ROOT, "assets"), "assets")],    # скопировать папку assets целиком
    excludes=["tkinter", "unittest", "pydoc", "typst", "numpy",
              "pygame.examples", "pygame.tests", "pygame.docs"],   # не включать лишнее
)
exe = EXE(..., name=NAME,
          console=False,                                 # не открывать чёрное окно консоли
          icon=...build/icon.ico... (только Windows),
          upx=False)                                     # не сжимать: UPX часто пугает антивирусы
coll = COLLECT(exe, a.binaries, a.datas, name=NAME)      # собрать всё в папку
```

`excludes` уменьшает размер и исключает инструменты разработки, которые программе не нужны.

`console=False` означает, что сообщения об ошибках собранной программы не видны. Если собранная программа не запускается, а из исходников работает — временно поставьте `console=True`, пересоберите и запустите из командной строки: ошибка будет напечатана.

### 18.3. `tools/package.py` и `ncorr/packaging.py`

`tools/package.py <windows|linux> <папка сборки> <папка для архивов>` вызывает `packaging.make_both`:
- в папку сборки (обычная версия) кладёт `README.txt` и `theory_ru.pdf`, `theory_en.pdf`;
- рядом делает копию `NeimarkCorrelation-dev` с меткой `_internal/assets/dev_edition.txt` — версию разработчика
  (в ней работает конструктор F12, PROJECT_GUIDE раздел 11);
- упаковывает обе: `NeimarkCorrelation-<платформа>-x64.zip` (для сайта) и `NeimarkCorrelation-dev-<платформа>-x64.zip`;
- для Linux помечает главный файл исполняемым (права `755`) прямо в zip.

`packaging.export_show` собирает обычную версию из версии разработчика копированием (её вызывает конструктор
при выходе из режима и команда `NeimarkCorrelation.exe --export`).

### 18.4. Linux-сборка в Docker

**Docker** запускает **контейнеры** — изолированные мини-системы Linux — прямо на Windows.

Команда:

```bash
docker run --rm -v "C:/idk/phys:/src" python:3.12-slim-bullseye sh /src/build/build_linux.sh
```

Разбор:
- `run` — запустить контейнер;
- `--rm` — удалить его после завершения;
- `-v "C:/idk/phys:/src"` — папка проекта видна внутри контейнера как `/src`, поэтому результат появляется прямо в `dist/`;
- `python:3.12-slim-bullseye` — **образ**: Debian 11 с установленным Python 3.12;
- `sh /src/build/build_linux.sh` — что выполнить внутри.

`build_linux.sh`:
1. ставит `binutils` (нужен PyInstaller на Linux);
2. ставит `pygame-ce` и `pyinstaller` тех же версий;
3. собирает в `/tmp/dist` внутри контейнера (так права файлов настоящие, Linux-овские);
4. упаковывает в `dist/NeimarkCorrelation-linux-x64.zip`.

**Почему именно Debian 11.** Программа, собранная на Linux, работает на системах с той же или более новой версией системной библиотеки **glibc**. В Debian 11 она старая (2.31), поэтому архив запускается на Ubuntu 20.04 и новее, Debian 11 и новее, Fedora 32 и новее, Astra Linux 1.7 и т. д. Если собирать на свежем Linux, на старых системах программа бы не запустилась.

### 18.5. Проверка Linux-архива

```bash
docker run --rm -v "C:/idk/phys:/src" ubuntu:20.04 sh /src/build/linux-test/run.sh ubuntu-20-04
```

`run.sh` ставит в чистую Ubuntu только виртуальный экран `xvfb` (Python там нет!), распаковывает архив, запускает программу с `--screenshot` и сохраняет снимки в `build/linux-test/`. `OK` в конце — программа запустилась. Последний аргумент — просто приставка к именам скриншотов.

Вместо `ubuntu:20.04` можно подставить `ubuntu:24.04`, `debian:12`. Для Fedora команды установки другие (`dnf`), поэтому `run.sh` там не подойдёт.

### 18.6. `tools/make_icon.py`

Рисует иконку (столбики затухающей корреляции с оранжевой кривой) и сохраняет `build/icon.png` и `build/icon.ico`. Формат ICO собирается вручную: заголовок плюс PNG внутри (так умеет Windows начиная с Vista). Поэтому Pillow не нужен.

## 19. Подводные камни

1. **Архив не обновился.** Правки в коде не попадают в `dist/` сами. Смотрите дату сборки, которую печатает `build.py`.
2. **Имена полей.** В `DemoScreen` поле `phase` — это фаза анимации. Однажды фазовую плоскость назвали тоже `self.phase`, и программа сломалась. Поэтому она называется `self.portrait`. Перед добавлением нового поля поищите, не занято ли имя.
3. **Виджет не добавлен в `self.widgets`.** Тогда он не рисуется и не реагирует на мышь, хотя создан.
4. **Не задан `rect` в `layout`.** Виджет будет размером 0×0 в левом верхнем углу — его не видно и не нажать.
5. **Надпись без ключа в `i18n.py`** → `KeyError` при запуске.
6. **Путь к файлу «вручную».** Пишите `res.path("img", "x.png")`, а не `"assets/img/x.png"` — иначе в собранной программе файл не найдётся.
7. **Картинки грузятся только после создания окна.** `convert_alpha()` в `resources.image` требует уже открытого окна. Не загружайте картинки на уровне модуля (при импорте).
8. **Тяжёлый расчёт в `draw` или каждом кадре.** Всё, что можно посчитать один раз, считается в `_recompute` или кэшируется (`values`, шрифты, страницы теории). Иначе программа будет тормозить.
9. **Символы шрифта.** Перед добавлением необычного символа (например, верхнего индекса) проверьте, что он есть в DejaVu. Иначе на его месте будет квадрат.
10. **`//` в Typst** — начало комментария (раздел 17.2).
11. **Docker.** Запускайте Docker Desktop вручную и дождитесь полной загрузки. Не запускайте его дважды подряд: однажды это привело к ошибке с файлом `dockerInference` при старте.
12. **Собранная программа открыта** во время сборки → не удаётся удалить `dist/windows`. Закройте её.
13. **Точность пресетов.** Не заменяйте выражения с `GOLDEN` на округлённые числа: точное марковское разбиение перестанет находиться.
14. **Целые и дробные.** Сдвиги (`lags`, индексы списков) — целые числа; `shift` и `cursor` — дробные. При индексации списка используйте `int(...)`.

## 20. Словарь программистских терминов

| Термин | Значение |
|---|---|
| **Модуль** | один `.py`-файл |
| **Пакет** | папка с `__init__.py`, содержащая модули |
| **Импорт** | подключение кода из другого модуля: `from ..physics import neimark` (`..` — на уровень выше) |
| **Класс, объект** | класс — «чертёж» (`Button`), объект — конкретная кнопка, созданная по нему |
| **Метод** | функция внутри класса; первый аргумент `self` — сам объект |
| **Поле (атрибут)** | переменная внутри объекта: `self.speed` |
| **Наследование** | класс берёт всё от родителя и меняет нужное: `class MenuScreen(Screen)` |
| **`super()`** | вызов метода родителя: `super().draw(surf)` рисует виджеты, как в `Screen` |
| **`@property`** | метод, читаемый как поле без скобок |
| **Лямбда** | короткая безымянная функция: `lambda: t("step")` |
| **Колбэк** | функция, которую передают, чтобы её вызвали позже (например, при клике) |
| **Замыкание** | функция, «запомнившая» переменные из места создания (`_chooser(v)`) |
| **Кэш** | сохранённые результаты, чтобы не считать повторно |
| **Событие** | сообщение от системы: клик, нажатие клавиши, изменение размера окна |
| **Главный цикл** | бесконечный цикл «события → обновление → рисование» |
| **Кадр** | один проход главного цикла; 60 в секунду |
| **`dt`** | время в секундах с прошлого кадра |
| **`Surface`** | картинка в памяти pygame, на которой рисуют; окно — тоже `Surface` |
| **`Rect`** | прямоугольник: `x`, `y`, ширина, высота, плюс удобные поля `center`, `bottom`, `right`… |
| **`blit`** | наложить одну картинку на другую |
| **`set_clip`** | ограничить рисование прямоугольником |
| **`SRCALPHA`** | картинка с прозрачностью |
| **Раскладка (layout)** | вычисление положения и размера элементов под размер окна |
| **Виджет** | элемент интерфейса (кнопка, ползунок) |
| **SDL** | библиотека на C, на которой построен pygame: окна, графика, ввод |
| **DPI** | плотность точек экрана; масштаб 125–150% в Windows |
| **Виртуальное окружение** | отдельная папка с Python и библиотеками проекта (`.venv`) |
| **PyInstaller** | инструмент, превращающий Python-программу в самостоятельную |
| **Docker, образ, контейнер** | Docker запускает изолированные системы; образ — их «шаблон», контейнер — запущенный экземпляр |
| **glibc** | основная системная библиотека Linux; её версия определяет совместимость |
| **Smoke test** | быстрый тест «запускается и не падает» |
| **seed** | число, задающее последовательность случайных чисел; одинаковый seed — одинаковый результат |
