## 1. Цель проекта и кто что делал

**Задание:** показать на одномерном осцилляторе с отрицательным трением, как из строго детерминированного
движения получается случайный процесс, и описать его корреляционной функцией. Обсудить появление
случайности из динамической неопределённости и точку бифуркации.

Логика проекта — цепочка, и код повторяет её:

```
уравнение движения ─► траектория ─► скорости yₙ при x = 0 ─► отображение yₙ → yₙ₊₁
        (neimark.py: Motion)                 (neimark.py: step)
                                                   │
             неустойчивость + точка ветвления y* ──┤──► случайность (две близкие траектории, motion.py)
                                                   │
                                                   └──► корреляционная функция R(k) (demo.py)
                                                        и её точная теория (markov.py)
```

| Часть | Автор | Файлы | Что показывает |
|---|---|---|---|
| Движение осциллятора | А. С. Григорьев (была веб-страница на HTML/JS, перенесена в приложение) | `ncorr/screens/motion.py`, класс `Motion` в `ncorr/physics/neimark.py` | груз на пружине, фазовая траектория, v(t) как проекция, отображение за полпериода; плюс две близкие траектории (добавлены, чтобы показать случайность и бифуркацию) |
| Корреляционная функция | В. А. Пупышев | `ncorr/screens/demo.py`, `ncorr/physics/markov.py`, `ncorr/physics/correlation.py`, `ncorr/ui/param_plane.py`, `ncorr/ui/phase_portrait.py` | пошаговое построение R(k) и C(τ), сравнение с точной теорией |
| Общее | оба | `app.py`, `menu.py`, `theory.py`, `authors.py`, `i18n.py`, `theme.py`, `ui/widgets.py`, `ui/plot.py`, сборка | окно, меню, языки, теория, авторы, архивы |

### 2.4. Как живёт любой экран

У каждого экрана (`screens/base.py`) пять методов, их вызывает `App`:

| Метод | Когда вызывается | Что делает |
|---|---|---|

одинаково на 1024×640 и на 2560×1440. Если что-то не влезает — меняют множитель при `u`.

`ui/plot.py`. Объект `Axes(rect, xlim, ylim)` хранит прямоугольник в пикселях и диапазоны по осям:

## 3. Физика в коде: `neimark.py`

Все величины безразмерные: время в единицах 1/ω (период 2π), скорость в единицах a (`A = 1.0`).

### 3.1. Параметры — класс `Params` (`neimark.py:17`)

```python
p = nm.Params(gamma, h)
p.s        # √γ — рост скорости за полпериода
p.delta    # δ = ln γ / 2π
p.lower    # −√γ·a — нижний край аттрактора
p.branch   # y* = −a/√γ — точка ветвления (бифуркации)
p.h_range()     # (γ − 1, 1 + √γ) — допустимые h/a при данном γ
p.is_chaotic()  # параметры внутри области хаоса?
```

`PRESETS` (`neimark.py:63`) — точки H и E из статьи: γ = φ², h = φ² − 1 и h = φ² (φ — золотое сечение).

### 3.2. Главная формула — `step` (`neimark.py:69`)

```python
def step(y, p):
    z = -p.s * y          # через полпериода скорость −√γ·y
    if z >= A:            # если она не меньше a — удар
        z -= p.h          # скорость уменьшается на h
    return z
```

Это $y_{n+1} = -\sqrt\gamma\,y_n - h\,\theta(-\sqrt\gamma\,y_n - a)$. **Её используют обе вкладки.**

### 3.3. Точное решение между ударами — `shape` и `position` (`neimark.py:90`, `:110`)

Если в момент прохождения x = 0 скорость равна y, то через время u (0 ≤ u ≤ π):

```python
x = y * position(u, delta)   # position(u, δ) = e^{δu} sin u
v = y * shape(u, delta)      # shape(u, δ)    = e^{δu} (δ sin u + cos u)
```

При u = π: `shape(π, δ) = −e^{πδ} = −√γ` — отсюда первая строка `step`.

### 3.4. Движение во времени — классы `HalfPeriod` и `Motion` (`neimark.py:115`, `:129`)

Это сердце части Саши. **Идея:** уравнение не интегрируется численно (никакого Рунге–Кутты). Между ударами
решение известно точно, поэтому движение хранится как **список полупериодов**:

```python
class HalfPeriod:         # один полупериод: от одного прохождения x = 0 до следующего
    n       # номер полупериода от начала движения
    t0      # момент начала
    y       # скорость в начале (после удара) — это и есть yₙ
    before  # скорость в конце ДО удара  (= −√γ·y)
    after   # скорость в конце ПОСЛЕ удара (= y следующего полупериода)
    hit     # был ли удар
```

Состояние `Motion`:

| Поле | Смысл |
|---|---|
| `p` | параметры |
| `t` | полное время с начала |
| `s` | время с начала текущего полупериода (0..π) |
| `halves` | список полупериодов, последний — текущий (`current`) |
| `crossings`, `hits` | счётчики прохождений x = 0 и ударов |
| `escaped` | движение ушло на бесконечность (|x| или |v| > `LIMIT = 10⁴`) |

Методы:

```python
mo = nm.Motion(p, v0)        # старт: x = 0, скорость v0
mo.advance(dt)               # продвинуть время на dt; вернёт число ударов
x, v = mo.state()            # x = y·position(s), v = y·shape(s) — точно
mo.pairs()                   # пары (yₙ, yₙ₊₁) для графика отображения
nm.Motion.near(mo, 1e-5)     # копия текущего состояния, скорость больше на 1e-5
```

**Как работает `advance(dt)`** (`neimark.py:169`):

```
пока dt > 0:
    осталось до конца полупериода left = π − s
    если dt < left:  s += dt  (просто едем дальше внутри полупериода)
    иначе:           dt −= left; конец полупериода → _cross()
```

**`_cross()`** (`neimark.py:190`) — момент прохождения x = 0:

```python
half.before = -p.s * half.y          # скорость до удара
half.after  = step(half.y, p)        # ТА ЖЕ формула, что и везде
half.hit    = half.after != half.before
halves.append(HalfPeriod(n + 1, t, half.after))   # начинается следующий полупериод
```

Следствия, которые стоит назвать на защите:
- **Точность.** Нет ошибки численного интегрирования: картинка совпадает с формулой до машинной точности.
- **Независимость от частоты кадров.** Продвинуть время на 25 одним куском или 2500 раз по 0.01 — результат
  одинаковый (тест `test_frame_independence`).
- **Период не зависит от амплитуды** (всегда π на полпериода), поэтому у двух близких траекторий
  прохождения x = 0 происходят в одни и те же моменты, и их можно сравнивать по номеру `n`.
- **Память.** Хранится около `HISTORY = 2000` последних полупериодов; старые удаляются пачками.
- **Покой.** Если y = 0, груз стоит в x = 0 (это неподвижная точка), время просто идёт.

### 4.5. Каждый график подробно

**1. Осциллятор — `_draw_oscillator`** (`motion.py:433`)
- Координата груза на экране: `bx = cx + x · scale`, где `scale = 0.38 · ширина / ext`.
- Пружина — ломаная из 18 зубцов от стенки до груза: длина меняется, число зубцов нет.
- Стрелка скорости: длина `v / ext · 5u`, направление по знаку v.
- Удар: если `flash > 0.15`, груз красный, вокруг центра расходится кольцо, сверху надпись «удар: v → v − h».
- Груз второй траектории — бирюзовый контур (пока траектории совпадают, он ровно под основным).
- Над полосой — легенда цветов (`draw_legend` из `demo.py`).

**2. Фазовая траектория — `_draw_phase`** (`motion.py:501`)
- Оси x и v от −ext до ext (квадрат).
- Траектория **не хранится по точкам**: для каждого из последних `PHASE_TRAIL` полупериодов функция
  `curve(half, δ, upto)` (`motion.py:45`) заново считает точки по точной формуле; для текущего — только до `s`.
  Старые полупериоды светлее (`shade` растёт с возрастом).
- Красный вертикальный отрезок на x = 0 — удар: от `half.before` до `half.after`.
- Синие точки на x = 0 — yₙ (если включены «Точки x = 0»).
- Красный пунктир v = a — порог удара. Фиолетовая точка — текущее состояние; бирюзовое кольцо — вторая траектория.

**3. v(t) — `_draw_timeline`** (`motion.py:564`) и **`_draw_curve_in_time`** (`motion.py:548`)
- Ось времени в единицах π; окно `_time_window()` шириной `TIME_WINDOW·π` едет за текущим моментом.
- **Вертикальная шкала та же, что у фазовой плоскости** (`-ext..ext`) и графики на одной высоте — поэтому
  проекция горизонтальна.
- Для каждого полупериода: точки `(t0 + u, y·shape(u))`, удары — красные скачки в моменты `t0 + π`,
  синие точки yₙ — в моменты `t0`.
- Бирюзовая кривая — вторая траектория (рисуется первой, поэтому пока совпадает — не видна).

**Проекция — `_draw_projection`** (`motion.py:582`): пунктир от `phase_ax.point(x, v)` до
`(time_ax.px(t/π), phase_ax.py(v))`. Высота одна и та же — это и есть проекция на ось v.

**4. Отображение — `_draw_map`** (`motion.py:595`)
- Голубой квадрат `[p.lower, a] × [p.lower, a]` — аттрактор (только в области хаоса).
- Серый пунктир — диагональ yₙ₊₁ = yₙ.
- Две синие прямые: правая `yₙ₊₁ = −√γ·yₙ` (от y* вправо, удара нет), левая `yₙ₊₁ = −√γ·yₙ − h`
  (от y* влево, удар). Вертикального соединения в разрыве нет.
- Фиолетовый вертикальный пунктир — y*. Кружки на концах ветвей: закрашенный `(y*, a − h)` и пустой `(y*, a)`
  показывают, какой конец принадлежит какой ветви.
- Фиолетовые точки — `motion.pairs()`, свежие ярче; последняя обведена. Бирюзовое кольцо — последняя пара второй траектории.

**5. Две траектории — `_draw_twins`** (`motion.py:641`)
- Верхний график: последние `TRACK` значений yₙ: основная — чёрные точки, вторая — бирюзовые кружки;
  фиолетовый пунктир — y*; красная вертикаль — момент расхождения `split_n`.
- Нижний график: `log10|Δyₙ|` (ось подписана степенями 10, функция `superscript`) и оранжевая прямая
  `log10 ε + (n − n0)·log10 √γ` — то есть ε·γ^(n/2).
- Подпись: «пока совпадают; разойдутся через ≈ …» или «разошлись через N полупериодов (оценка …)»,
  оценка `ln(1/ε)/ln√γ`.

### 4.6. Две траектории: как найти момент расхождения

- `_restart_twin()` (`motion.py:102`): `twin = Motion.near(motion, ε)` — копия **текущего** состояния со
  скоростью больше на ε. Вызывается при «Заново» и при выборе ε, поэтому опыт можно повторить в любой момент.
- `_record(first)` (`motion.py:200`) после каждого продвижения:
  1. ищет первый полупериод, в конце которого **одна траектория получила удар, а другая нет**
     (`a.hit != b.hit`) — это момент, когда разница дошла до y*. Его номер + 1 → `split_n`;
  2. дописывает `(n, yₙ, yₙ второй)` в `track` (хранит последние `TRACK + 1`).
- Полупериоды сопоставляются по номеру: `_half(mo, n)` (`motion.py:195`) находит полупериод номер n в
  списке `mo.halves`.
- `_advance` (`motion.py:179`), пока `split_n` не найден, двигает время кусками по 500 полупериодов —
  иначе на большой скорости момент расхождения мог бы выпасть из хранимой истории.

Физика: пока обе скорости по одну сторону от y*, они на одной ветви, и разница умножается ровно на √γ за
полупериод. Тест `test_nearby_trajectory` проверяет это и оценку: для точки H расхождение на 12, 25, 40
полупериоде при оценках 9.6, 23.9, 38.3.

## 5. Вкладка «Корреляционная функция»

Подробно — CODE_GUIDE, разделы 8, 9 и 13. Здесь — суть, чтобы рассказать.

**`demo.py`.** При смене параметров `_recompute()` генерирует `N` значений yₙ функцией `nm.sequence`
(та же `step`), считает теорию и создаёт `Estimator`. Анимация одного шага (`update`):
сдвиг копии (`SHIFT_END`) → появление произведений (`PRODUCT_END`) → рост столбика. Четыре графика:
процесс, сдвинутая копия, наложение с произведениями, R(k). Режим `c` — то же для непрерывной v(t)
(`nm.velocity`, 16 отсчётов на полпериод).

**`correlation.py`.** `Estimator(data)` один раз считает среднее и отклонения, а `normalized(k)` — среднее
произведений `(yᵢ − ȳ)(yᵢ₊ₖ − ȳ)` / дисперсия. `Running` — то же самое, но накапливаемое по одному значению
(используется в тесте связи вкладок).

**`markov.py`** — точная теория. Образы краёв аттрактора и точки ветвления делят отрезок
`[−√γ, 1]` на интервалы, которые отображение переводит в объединения интервалов (марковское разбиение;
в точке H их 2, в E — 3). Стационарная плотность кусочно-постоянна, а оператор Перрона–Фробениуса переводит
кусочно-линейные функции в кусочно-линейные — поэтому ⟨y₀yₖ⟩ считается точно конечными суммами.

## 6. Как связаны вкладки

**Переключатель** — один общий объект `app.tabs` (`Segmented`, `app.py:55`). Оба экрана кладут его первым
в свой `self.widgets` и задают место `self.tabs_rect` в своём `layout`. `App._layout` (`app.py:82`) ставит
переключатель туда, куда скажет **активный** экран — так же, как кнопку языка (`lang_rect`).

```
клик по вкладке ─► Segmented ─► App._switch_tab(name)          app.py:77
                                  ├─ если "demo": motion.sync_correlation()
                                  └─ App.show(name)            app.py:97 (отмечает вкладку, enter(), layout)
```

**Параметры.** `sync_correlation()` (`motion.py:156`) передаёт γ и h на вкладку корреляции **только если их
меняли** на вкладке движения (сравнение с `_synced`). Там они прижимаются к области хаоса
(`demo.use_params` → `param_plane.clamp`), потому что вне её корреляционная функция не определена.
Если на вкладке движения ничего не трогали, вкладка корреляции сохраняет свои параметры.

**Меню** (`menu.py`): «Демонстрация» → `app.show("motion")`; «Назад» на обеих вкладках → меню;
Escape — тоже в меню (`App._handle`).

Открыть файлы в таком порядке — это пересказ всей идеи:

1. **`neimark.py:69` — `step`.** «Вся физика проекта — эти четыре строки: через полпериода скорость
   умножается на −√γ, а если она не меньше a, то удар уменьшает её на h».

5. **`motion.py:200` — `_record`.** «Две траектории с разницей ε; момент расхождения — когда одна получила

6. **`demo.py` — `_recompute`, `update`.** «Генерируем ряд той же `step`, анимация: сдвиг → произведения → столбик».

8. **`tests/`.** «Физика проверена по статье: значения R(k) в точках H и E совпадают с рис. 5».

## 10. Вопросы по коду и ответы

**Почему не numpy / matplotlib?**
Чтобы архив был маленьким и гарантированно запускался на любом компьютере без установки. Вычислений немного:
выборки до 100 000 чисел, на чистом Python это доли секунды.

**Почему вы не решаете дифференциальное уравнение численно?**
Между ударами оно линейное и решается точно: x = y e^{δu} sin u. Численный метод добавил бы ошибку, которая в
хаотической системе растёт как γ^{n/2} и через несколько десятков полупериодов исказила бы траекторию. Поэтому
движение считается по событиям (`Motion`).

**Как анимация связана со временем? Что если компьютер медленный?**
`update(dt)` получает реальное время между кадрами, `advance(dt · speed)` продвигает физику ровно на столько.
Результат не зависит от того, какими кусками продвигать (тест `test_frame_independence`).

**Откуда берётся случайность, если в коде нет `random`?**
На вкладке движения `random` нет вообще. Случайность — из неустойчивости: разница ε растёт в √γ раз за полпериод
и у точки ветвления y* превращается в «удар/нет удара». Это показывает вторая траектория.
(`random` есть только в `sequence` на вкладке корреляции — чтобы выбрать начальную точку; дальше тоже только `step`.)

**Как понять, что всё правильно?**
Тесты `tests/test_physics.py`:
- `test_crossings_follow_the_map` — движение во времени даёт ту же последовательность yₙ, что и `step`;
- `test_kick_jump` — удар уменьшает скорость ровно на h;
- `test_nearby_trajectory` — рост ε·γ^{n/2} и момент расхождения;
- `test_point_h`, `test_point_e` — R(k) совпадает со статьёй (рис. 5);
- `test_correlation_from_motion` — R(k) по yₙ из движения во времени совпадает с теорией: **обе вкладки
  моделируют один процесс**.

`tests/test_ui_smoke.py` нажимает все кнопки обеих вкладок без окна.

**Почему период не зависит от амплитуды, и зачем это коду?**
Уравнение линейное, частота 1. Поэтому прохождения x = 0 у двух близких траекторий одновременны, и их можно
сравнивать по номеру полупериода (`HalfPeriod.n`, `_half`).

**Что будет, если выйти из области хаоса?**
На вкладке движения можно: при слабом ударе движение уходит на бесконечность, `Motion.escaped` останавливает
опыт и показывает сообщение. На вкладке корреляции параметры прижимаются к области (`clamp`), потому что
вне неё процесс не стационарен.

**Чем ваш перенос отличается от веб-версии А. С. Григорьева?**
Физика та же (у него удар при v > a, у нас при v ≥ a — различие только в одной точке). Не перенесены выгрузка
точек в CSV и отдельная заставка выхода. Добавлены две близкие траектории и связь с вкладкой корреляции.

## 11. Конструктор оформления (режим разработчика)

Позволяет **мышью** двигать и растягивать кнопки, ползунки, переключатели, заголовки разделов **и графики**,
менять размер шрифта, любые надписи на обоих языках, цвета и общий шрифт. Всё меняется на экране сразу.
При выходе из режима программа сама собирает обычную версию для показа.

### 11.1. Две версии программы

Сборка (`tools/build.py`) делает из одной и той же программы две:

| Версия | Папка | Архив | Для кого |
|---|---|---|---|
| **обычная** | `dist/windows/NeimarkCorrelation` | `dist/NeimarkCorrelation-windows-x64.zip` | для показа и сайта; конструктора в ней нет |
| **разработчика** | `dist/windows/NeimarkCorrelation-dev` | `dist/NeimarkCorrelation-dev-windows-x64.zip` | для себя: F12 включает конструктор |

Версии отличаются **только** файлом-меткой `_internal/assets/dev_edition.txt` внутри версии разработчика.
Поэтому версия разработчика может сама сделать обычную: скопировать свою папку без метки, положить туда
текущее оформление и упаковать в zip. Ни Python, ни PyInstaller для этого не нужны — работает на любом
компьютере за несколько секунд.

При запуске из исходников (`.venv/Scripts/python main.py`) конструктор тоже работает.

### 11.2. Как пользоваться

1. Запустить **версию разработчика** (`NeimarkCorrelation-dev/NeimarkCorrelation.exe`) или программу из исходников.
2. Открыть нужный экран (вкладку) и нажать **F12**. Обведены всё, что можно двигать: **синим** — кнопки,
   ползунки и заголовки разделов, **зелёным** — графики. Внизу слева — тёмная панель конструктора: её можно
   перетащить за фон, а **Tab** сворачивает её в одну строку, чтобы не мешала.
3. **Щелчок** — выбрать (оранжевая рамка). **Перетаскивание** — сдвинуть. **Оранжевый уголок** справа внизу —
   изменить размер. **Стрелки** — сдвиг на 0.1u, с Shift — на 1u, с Alt — размер.
   График двигается вместе со своим заголовком. Если сдвинуть по высоте график v(t) относительно фазовой
   плоскости, пунктир-проекция станет наклонной — это нормально, она всё равно соединяет текущие точки.
4. **Двойной щелчок по любой надписи** — изменить её: заголовки графиков, подписи осей (`x`, `v`, `t / π`, `yₙ`…),
   уровни `a` и `y*`, `|Δyₙ|`, легенды, формулы, строки информации, кнопки, вкладки, шапка меню.
   Меняется именно та надпись, по которой щёлкнули: одинаковый текст в другом месте (например, «t / π» на
   другой вкладке) не затрагивается. В надписях с числами (`Прохождений x = 0: 12`) меняется шаблон, числа
   подставляются сами. Не меняются только числа на делениях осей.
5. Кнопки панели:

| Кнопка | Что делает |
|---|---|
| Текст элемента (Enter) | изменить надпись выбранного элемента на текущем языке; у графика — его заголовок |
| Шрифт − / Шрифт + | размер шрифта выбранного элемента (у графиков — через «Весь текст») |
| Сбросить элемент (Delete) | вернуть элементу положение, размер и шрифт из кода |
| Все тексты | список **всех** надписей программы с поиском: заголовки графиков, шапка меню, подписи |
| Цвета | все цвета программы с пояснением, что ими нарисовано; ползунки R, G, B |
| Шрифт: без засечек / с засечками | общий шрифт программы |
| Весь текст − / + | общий размер шрифта всей программы |
| Отменить (Ctrl+Z) | отменить последнее действие (до 100 шагов) |
| Сохранить (Ctrl+S) | записать всё в `design.json` |
| Собрать обычную версию | сохранить и собрать обычную версию прямо сейчас, не выходя из режима |
| Сбросить всё | (нажать дважды) вернуть оформление из кода |
| Выйти (F12) | выйти из режима — см. 11.3 |

6. Пока режим включён, кнопки демонстрации не нажимаются (щелчок выбирает элемент). Чтобы перейти на другой
   экран — F12, перейти, снова F12. Положения запоминаются **для каждого экрана отдельно**.
7. Чтобы поменять надпись на другом языке: выйти из режима, переключить язык кнопкой English/Русский,
   снова F12 и открыть надпись.

**Важно про тексты:** в надписях вида `Прохождений x = 0: {n}` поля в фигурных скобках не трогайте — туда
программа подставляет числа. Если поле испортить, программа покажет исходную надпись.

### 11.3. Что происходит при выходе из режима

При **F12** или **закрытии окна** в режиме разработчика:
1. правки сохраняются в `design.json`;
2. если оформление изменилось с прошлой сборки, собирается обычная версия. Внизу окна видна строка
   «идёт сборка обычной версии…», потом — где лежит результат. Если закрыть окно, программа дождётся конца
   сборки и только потом завершится.

Куда кладётся обычная версия:

| Откуда запущен конструктор | Обычная версия | Как собирается |
|---|---|---|
| версия разработчика, например `D:\neimark\NeimarkCorrelation-dev\` | `D:\neimark\NeimarkCorrelation\` и `D:\neimark\NeimarkCorrelation-windows-x64.zip` | копированием, несколько секунд |
| исходники, сборка не старее кода | `dist/windows/NeimarkCorrelation/` и `dist/NeimarkCorrelation-windows-x64.zip` | копированием из `dist/windows/NeimarkCorrelation-dev`, несколько секунд |
| исходники, код менялся после сборки | там же | полной сборкой `tools/build.py --no-tests` (около минуты), журнал — `build/dev-build.log` |

«Не старее кода» проверяется по дате файлов: если любой файл в `ncorr/`, `assets/` (кроме `design.json`),
`main.py` или `build/neimark.spec` новее версии разработчика, копированием обойтись нельзя — нужна полная сборка.

Если обычная версия в этот момент **запущена**, её папку нельзя заменить: появится сообщение
«обычная версия не собрана… закройте её». Закройте и нажмите «Собрать обычную версию».

Собрать обычную версию можно и без окна:

```bash
NeimarkCorrelation-dev/NeimarkCorrelation.exe --export
```

### 11.4. Как это устроено

```
ncorr/devmode.py    конструктор: выбор, перетаскивание, панель, окна «Все тексты» и «Цвета», сборка при выходе
ncorr/design.py     хранилище правок: чтение/запись design.json и применение к программе
ncorr/packaging.py  две версии и архивы: make_both (при сборке), export_show (из версии разработчика)
design.json         правки: в исходниках — assets/design.json, в собранной программе — _internal/assets/design.json
                    (появляется после первого «Сохранить»; удалите — вернётся оформление из кода)
```

Файл `design.json` хранит **только отличия** от кода:

```json
{
 "widgets": {"motion.b_run": {"dx": 3.0, "dy": -2.0, "fs": 1.1},
             "motion.graph.map": {"dx": 2.0, "dw": -1.0}},
 "colors":  {"SHIFTED": [200, 95, 190]},
 "texts":   {"ru": {"reset": "Сначала"}, "en": {}},
 "font":    {"scale": 1.05, "serif": false}
}
```

- **Положения** записаны как сдвиг `dx, dy` и изменение размера `dw, dh` **в единицах u** (u ≈ высота окна / 52),
  а не в пикселях. Поэтому правка остаётся правильной при любом размере окна и на любом мониторе.
  `fs` — множитель шрифта элемента.
- **id элемента** — `экран.имя`: `motion.b_run` — поле `self.b_run` экрана `motion`; `menu.buttons[0]` — первая
  кнопка меню; `motion.label.sec_twin` — заголовок раздела; `motion.@tabs`, `motion.@lang` — переключатель
  вкладок и кнопка языка; `motion.graph.map` — график.
- **Графики** экран перечисляет в словаре `GRAPHS` (`motion.py`, `demo.py`): имя → (оси, заголовок). Чтобы новый
  график тоже двигался, достаточно добавить его туда.
- **Применение:** экран сначала раскладывает всё как обычно (`layout`), а в конце `App._layout` функция
  `design.apply_layout` сдвигает элементы по `design.json`. Сам код раскладки не меняется.
- **Какая надпись под мышью:** в режиме разработчика каждый кадр записывается, какой текст где нарисован
  (`widgets.DRAWN`) и каким ключом `i18n.t` он получен (`i18n.TRACE`). Поэтому двойной щелчок находит именно
  нужный ключ, даже если такой же текст есть в другом месте. Все подписи графиков — тоже ключи в `i18n.py`
  (они начинаются на `g_`, например `g_t`, `g_ystar`, `g_dy`).
- **Цвета** подменяют значения в `theme.py` (`design.apply_global`), **тексты** — в `i18n.t`
  (`i18n.OVERRIDES`), **шрифт** — в `resources.font` (`resources.FONT`).
- **Какая версия:** `devmode.allowed()` — из исходников всегда, в собранной программе — только если есть
  метка `dev_edition.txt`. В обычной версии F12 ничего не делает.

Тесты: `test_dev_mode` — сдвиг мышью, шрифт, текст, заголовок, цвет, график (в том числе размер), отмена,
сохранение и загрузка; `test_two_editions` — обе версии при сборке, сборка обычной версии из версии
разработчика (без метки, с новым оформлением, в zip), повторная сборка поверх старой.

### 11.5. Числа программы: `assets/config.json`

Все важные числа вынесены в один файл `assets/config.json` — без них не нужно лезть в код:

| Раздел | Что там, например |
|---|---|
| `physics` | порог «ушло на бесконечность» (`limit`), сколько полупериодов хранить (`history`) |
| `motion` | след на фазовой плоскости (`phase_trail`), окно v(t) (`time_window`), гладкость кривых (`curve_samples`), сколько yₙ на графике двух траекторий (`track`, было 40), варианты ε (`twins`) и какое выбрано при запуске, скорость анимации и её пределы, пределы ползунков γ, h/a, v₀, параметры сценариев «Нормальный режим» и «Без ударов» |
| `demo` | длина выборки N и пределы ползунка, сколько столбиков R(k) (`kmax`) и C(τ) (`c_steps`), отсчётов на полпериод, доли анимации шага, ширина окна просмотра, номер реализации (`seed`), пределы γ на плоскости параметров |
| `window` | наименьший размер окна при запуске, кадров в секунду |

Как менять:
- **в режиме разработчика:** кнопка **«Числа (config)»** — список всех чисел с пояснениями; щелчок по строке —
  ввести новое значение, Enter — применить. Экраны сразу перестраиваются с новыми числами (анимация
  начинается заново). Значение прижимается к допустимым пределам; если ввести не число, ничего не изменится.
  Изменённые числа выделены оранжевым. Кнопки: **«Открыть config.json»** — открыть файл в текстовом редакторе,
  **«Перечитать файл»** — применить правки, сделанные в редакторе, **«Всё по умолчанию»** (дважды).
  «Отменить» (Ctrl+Z) отменяет и правки чисел;
- **вручную:** открыть `assets/config.json` любым редактором. В конце файла раздел `"_описание"` — что значит
  каждое число. Если число удалить или файл испортить, берётся значение по умолчанию.

`config.json` попадает в обе версии программы и в обычную версию, собранную из версии разработчика
(в собранной программе он лежит в `_internal/assets/config.json`).

**Как устроено в коде** (`ncorr/config.py`): список `SCHEMA` — все числа с значением по умолчанию, пояснением и
пределами. В коде числа читаются как `config.motion.track`, `config.demo.kmax`. Модули, которым числа нужны
как константы (`motion.py`, `demo.py`, `param_plane.py`, класс `Motion`), получают их в `refresh()`;
`App.rebuild()` вызывает `refresh()` и пересоздаёт экраны. Чтобы добавить новое число — строка в `SCHEMA`
и чтение `config.раздел.ключ` в нужном месте.
